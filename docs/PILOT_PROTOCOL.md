# 업무효과 실증 절차

## 1. 이 기능의 목적과 현재 상태

업무효과 측정 패널은 **공무원이 실제로 수행한 두 방식의 업무를 같은 참가자 안에서 비교**하기 위한 기록 도구다. 서구온이 시간을 줄였거나 오류를 줄였다는 성과값을 미리 넣지 않는다. 처음 열면 빈 상태이며, 사용자가 실제 측정·채점한 값을 저장한 뒤에만 비교한다.

현재 측정 대상은 `공간 운영대안 비교`와 `현장변경 재검토` 두 과제다. 시간만 짧아졌다는 이유로 개선이라고 판정하지 않도록 오류와 출처누락을 함께 기록한다. 자료 조회 기능 수, API 연결 수, AI 응답 길이는 업무효과 지표로 사용하지 않는다.

이 패널은 측정값의 자동 수집·독립 검증 시스템이 아니다. 수행시간·순서·채점 결과는 입력한 기록이다. 실제 업무효과를 주장하려면 과제지, 자료 버전, 익명 결과물, 채점표를 함께 보관하고 담당자 검토를 거쳐야 한다.

## 2. 시험 전에 준비할 것

| 준비 항목 | 기록할 내용 |
| --- | --- |
| 익명 참가자 ID | 예: `P001`. 이름·연락처·직원번호를 쓰지 않음 |
| 대표과제 | 아래 두 과제 중 하나 |
| 공통 측정조건 ID | 같은 과제지·자료·평가기준 묶음의 이름. 예: `round1` |
| 공통 조건 메모 | 과제지 번호, 자료 버전·기준일, 비교 대상, 시간 범위, 도구 버전, 제공 안내, 완료기준, 정답표·채점표 번호 |
| 실제 수행순서 | `AB`: 기존방식 → 서구온, `BA`: 서구온 → 기존방식 |
| 수행일 | 실제 과제를 수행한 날짜. 입력 시각과 별도 |
| 결과물 식별자 | 각 방식의 익명 산출물 파일 또는 보관 번호 |

같은 참가자는 같은 ID를 계속 쓴다. 참가자마다 실제로 어떤 순서로 수행했는지 기록하고 AB와 BA가 한쪽에만 몰리지 않도록 시험 전에 순서를 정한다. 현재 도구가 순서를 무작위 배정하거나 실제 수행순서를 자동 감시하지는 않는다.

같은 조건 ID의 공통 메모는 같은 내용으로 유지한다. 참가자별 도움, 중단, 기기 장애 등의 차이는 각 방식의 결과물·채점 근거 칸에 적는다. 자료 버전이나 완료기준이 바뀌면 새 조건 ID를 사용한다. 기록이 불일치한 채로 합쳐서 요약하지 않는다.

기존방식의 허용 도구를 먼저 정한다. 실제 사용하던 문서·표계산·지도·공공자료 검색 절차를 재현하되 두 방식이 같은 자료와 같은 완료기준에 접근할 수 있게 한다. 서구온 쪽만 이미 정리한 정답이나 추가 도움을 제공한 경우에는 그 차이를 기록하고 시험 해석에 반영한다.

## 3. 대표과제와 완료 산출물

### 과제 A: 공간 운영대안 비교

**업무 상황:** 주민 모임 또는 생활 프로그램에 쓸 공공공간의 운영 조건을 검토한다. 시험 담당자는 같은 공간 목록, 검토할 요일·시작·종료 시각, 확인된 운영 상태, 두 변경안의 가정을 준비한다. 처음 시험에서는 3개 안팎의 공간처럼 검토 가능한 작은 범위로 시작할 수 있다. 이는 과제 구성 예시이며 실증 결과가 아니다.

**참가자에게 요청할 산출물:**

1. 현재 확인 상태와 두 변경안을 같은 기준으로 비교한 표
2. 요청 시간 전체 이용 가능한 공간 수, 확인이 필요한 공간 수, 공간별 겹치는 운영시간 합계
3. 비용을 입력했다면 추가 연간 운영비의 합계와 입력 가정. 미입력 비용은 미산정 처리
4. 공개자료의 출처·기준일과 담당자 확인 근거
5. 최종 선정 전에 추가로 확인해야 할 운영·예약·관리 조건

정답표는 같은 자료와 계산 규칙을 사용해 별도로 준비한다. 운영 상태가 확인되지 않은 공간을 이용 가능으로 확정하거나, 공간의 시간 합계를 주민 수혜 인원으로 바꾸는 것은 잘못된 결과다. 비교표가 완성됐다고 공식 예약이나 사업 승인이 완료된 것은 아니다.

### 과제 B: 현장변경 재검토

**업무 상황:** 기존 검토 뒤 공간의 운영시간·휴관 등의 변경 통보가 들어왔다. 시험 담당자는 동일한 이전 검토와 날짜·확인 근거가 있는 변경 통보를 두 방식에 제공한다.

**참가자에게 요청할 산출물:**

1. 변경된 공간과 확인일·근거가 있는 최신 상태 기록
2. 같은 요일·시간·공간 범위에서 다시 계산한 비교
3. 이전 저장 결과와 달라진 항목 및 달라진 이유
4. 이전 결과가 과거 시점의 기록임을 보존한 설명
5. 여전히 미확인인 조건과 재확인 필요 항목

실제 변경 통보를 사용하면 출처와 처리 권한을 확인한다. 교육용 가상 통보를 사용했다면 공통 조건 메모에 명시하고, 이 결과를 실제 시설 운영 개선이나 주민 편익의 실증으로 표현하지 않는다. 가상 과제를 실제 사람이 수행한 시간은 사용성 관찰 자료가 될 수 있으나 정책 성과와는 구분한다.

## 4. 시간과 품질을 같은 방식으로 재기

### 완료시간

시험 담당자가 과제지와 필요한 자료를 제공하고 시작을 알린 때부터, 참가자가 첫 완성본을 제출한 때까지의 초를 기록한다. 현재 화면은 수동 입력 방식이므로 별도 시계·타이머를 사용한다. 1~86,400초의 값만 저장한다.

대기·검색·외부 자료 확인·AI 응답 대기를 포함할지, 교육과 사전 연습을 어디까지 제공할지 먼저 정해 공통 메모에 남긴다. 참가자별로 다른 규칙을 적용하면 안 된다. 휴식·연결 장애·추가 설명이 있었다면 결과물·채점 근거에 기록한다. 제출 뒤 채점자가 발견한 오류의 수정 시간을 첫 제출 시간에 임의로 섞지 않는다. 수정까지 측정하려면 별도 과제·조건을 정한다.

### 오류 건수

시험 전에 정한 채점표의 검토 항목 가운데 잘못된 결과가 있는 항목 수다. 예를 들어 잘못된 공간 선택, 시간 범위의 불일치, 확인하지 않은 운영 상태를 확정한 처리, 틀린 계산, 이전 기록의 훼손 등을 항목으로 정할 수 있다. 같은 원인에서 반복 표시된 값을 몇 건으로 셀지는 사전에 정한다.

정답표의 항목 수와 난도가 다른 시험의 오류 건수를 한데 비교하지 않는다. 현재 패널은 **오류 건수**를 보관하며 오류율을 산출하지 않는다. 채점 대상 항목 수가 필요하면 공통 조건 또는 채점표에 함께 기록한다.

### 출처누락 건수

채점표에서 필수로 정한 출처·기준일·확인 근거 가운데 빠진 항목 수다. 기준일이 원자료에 없는 경우 `미제공`이라고 밝혔는지와, 존재하는 기준일을 누락했는지를 구분한다. 잘못된 출처를 쓰는 오류와 아예 쓰지 않은 누락의 구분 기준도 정한다. 두 지표를 합쳐 종합 오류율을 만들지는 않는다.

두 방식의 결과물을 가능한 한 같은 검토자가 같은 기준으로 채점하고, 결과물·채점표 번호를 기록한다. 아직 채점하지 않은 오류나 출처누락은 빈칸이다. `0`은 채점 결과 없음을 확인한 경우에만 입력한다. 한 방식의 시간·오류·누락·근거 네 항목이 모두 준비된 뒤 저장할 수 있다.

## 5. 패널 사용 순서

1. `업무효과 측정`을 연다. 참가자 ID, 수행일, 과제, 조건 ID, 실제 순서를 입력한다.
2. 공통 측정조건과 채점 기준을 적는다.
3. A 기존방식과 B 서구온의 실제 완료시간·오류·출처누락·결과물 근거를 입력한다. 한 방식만 마쳤으면 다른 방식은 전부 비워 둔다.
4. `측정 저장`을 누른다. 한 방식만 있는 기록은 대기 상태로 남고 요약 산정에서 제외된다.
5. 이후 같은 참가자의 기록을 `수정`하여 나머지 방식을 추가한다. 같은 참가자·과제·조건으로 새 기록을 중복 생성하면 오류를 안내한다.
6. 입력을 고치면 새 수정 이력이 생긴다. 시험 조건이 달라졌거나 중단한 기록은 `요약에서 제외`를 눌러 사유와 함께 남긴다. 삭제된 것으로 숨기지 않고 원기록을 보존한다.
7. 제외한 기록은 `수정하여 복원`으로 다시 검토할 수 있다. 복원할 때 같은 참가자·과제·조건의 다른 활성 기록이 있으면 중복을 먼저 해결한다.
8. `원본 이력 CSV`와 `전체 기록 JSON`으로 결과를 보관한다. 입력 취소·수정 취소는 아직 저장하지 않은 초안만 취소한다.

저장은 현재 브라우저의 지역별 localStorage를 사용한다. 이 기능은 측정값을 서버로 전송하지 않는다. 다른 컴퓨터·브라우저·계정과 자동 공유되지 않으며, 브라우저 데이터 삭제 시 사라질 수 있다. 공동업무 저장소와 승인·감사 시스템을 갖춘 상태라고 주장하지 않는다. 현재 UI는 파일 내보내기를 제공하며 파일을 다시 가져오는 화면은 제공하지 않는다.

## 6. 계산 방식과 해석

비교 단위는 **같은 지역·같은 참가자·같은 대표과제·같은 조건 ID의 두 방식**이다. 과제 A와 B를 섞거나, 다른 참가자의 기존방식 기록과 서구온 기록을 연결하지 않는다. 수정 전 기록과 제외 기록도 효과 계산에 중복 사용하지 않는다.

각 참가자에 대해 다음 차이를 계산한다.

- 완료시간 감소 = 기존방식 초 − 서구온 초
- 시간 감소율 = (기존방식 초 − 서구온 초) ÷ 기존방식 초 × 100
- 오류 감소 = 기존방식 오류 건수 − 서구온 오류 건수
- 출처누락 감소 = 기존방식 출처누락 건수 − 서구온 출처누락 건수

양수는 서구온에서 감소했음을, 음수는 증가했음을 뜻한다. 시간 감소율이 음수이면 서구온 쪽이 더 오래 걸린 것이다. 음수를 0으로 바꾸거나 불리한 기록을 자동 제외하지 않는다.

같은 과제·조건에서 두 방식을 모두 완료한 **서로 다른 참가자 3명 이상**이 있고 공통 조건 메모가 일치하면 각 참가자의 차이들의 중앙값을 표시한다. `두 집단 중앙값의 차이`나 `전체 시간 합계의 비율`로 대체하지 않는다. 짝수가 되면 가운데 두 값의 평균을 중앙값으로 쓴다. 개별 차이는 표본이 적어도 확인할 수 있지만 집단 요약은 미산정 상태로 둔다.

3명은 이 화면의 요약 표시 기준이다. 통계적으로 효과를 입증하기에 충분한 표본수라는 뜻이 아니다. 신뢰구간, 통계적 유의성, 모집단 효과를 계산하지 않는다. AB/BA 수를 함께 표시하고 순서가 한쪽에만 있으면 연습·순서 효과 가능성을 알린다. AB/BA가 모두 있더라도 충분한 통제나 인과효과가 입증되는 것은 아니다.

시간이 줄고 오류가 늘어난 결과는 품질과 속도의 교환을 보여 준다. 이를 한 숫자나 점수로 합쳐 개선으로 단정하지 않는다. 담당 부서와 사용자가 어떤 오류가 업무상 중요한지 검토하고, 참가자의 실제 사용 경험과 함께 개선할 부분을 정한다.

보고할 때는 다음 내용을 함께 적는다.

- 참가자 수, 직무·경험의 익명화된 범위와 모집 방법
- 과제·자료·도구 버전, 수행일, AB/BA 분포
- 완료된 비교 수, 미완료 수, 제외 사유와 기록 수
- 개인별 원자료와 차이, 중앙값, 오류 및 출처누락의 변화
- 반복 과제 학습, 자율 입력, 채점 편차, 기기·네트워크 등의 한계

## 7. 원자료와 이력 내보내기

CSV는 각 이력마다 기존방식과 서구온 두 행을 내보낸다. 아직 입력하지 않은 방식은 `observed=false`이고 수치는 빈칸이다. `0`으로 만들지 않는다. 수정·제외 전 이력도 포함된다.

| CSV 열 | 의미 |
| --- | --- |
| `region_id`, `record_id`, `revision` | 지역, 논리적 측정 ID, 수정 이력 번호 |
| `is_latest` | 해당 기록의 가장 최근 이력인지 |
| `latest_state` | 해당 기록의 현재 상태: `active` 또는 `excluded`. 과거 행에도 현재 상태를 표시 |
| `event_action` | 이 이력이 저장(`record`)인지 제외(`void`)인지 |
| `participant_id`, `task_id`, `condition_id` | 비교 연결 기준 |
| `sequence`, `session_date`, `common_conditions` | 실제 순서, 수행일, 공통 조건 |
| `method`, `observed` | `baseline`/`seoguOn`, 실제 기록 유무 |
| `seconds`, `errors`, `source_omissions` | 입력한 측정값. 없는 값은 빈칸 |
| `evidence`, `entered_at`, `void_reason` | 근거, 입력 시각, 제외 사유 |

CSV로 다시 집계할 때는 먼저 `is_latest=true`, `latest_state=active`, `event_action=record`인 행을 선택하고, 같은 `record_id`의 두 방식이 모두 `observed=true`인지 확인한다. 모든 행을 그대로 합산하면 수정 이력까지 중복 계산된다.

CSV의 텍스트가 `=`, `+`, `-`, `@` 등으로 시작하면 스프레드시트 수식으로 실행되지 않도록 작은따옴표를 붙인다. 앞에 공백·탭이 있는 경우도 처리하고 쉼표·따옴표·줄바꿈을 인용한다. JSON에는 입력한 텍스트와 수정 이력을 그대로 보관하므로 원문 보존에는 JSON도 함께 보관한다. 텍스트가 외부 URL이라고 하더라도 도구가 접속하지 않는다.

기록 한도는 이력 2,000개와 직렬화한 JSON 2MiB다. 한도를 넘거나 저장에 실패하면 기존 기록을 유지하고 알린다. 기존 저장본을 읽지 못한 경우 빈 기록으로 덮어쓰지 않고 읽지 못한 원본을 별도로 보관할 수 있게 한다.

## 8. 구현 검사와 다음 실증

`tests/pilot-measure.test.mjs`에서 빈 상태, 미완료 비교, 개인별 차이·중앙값, 과제·조건 분리, 조건 불일치, 수행순서 경고, 음수 개선량, 수정·제외·복원, 참가자 중복, 날짜·입력 오류, 지역별 저장, CSV 수식 방어와 원본 이력 보존을 검사한다. 이 자동 테스트가 증명하는 것은 계산과 기록 규칙이다. 실제 공무원이 더 빨리, 더 정확하게 일했다는 증거는 아니다.

다음 실증에서는 실제 사용자와 소관 부서가 과제지를 함께 정하고, 같은 기준으로 수집한 실제 측정값과 익명 결과물을 축적한다. 결과가 기대와 다르면 그 기록도 남겨 화면·자료·업무 흐름을 고친다. 경쟁·발표용 점수는 이런 검증 수준을 포함하여 별도로 평가하며, 측정 패널이 생겼다는 이유만으로 목표 점수를 달성했다고 표현하지 않는다.
