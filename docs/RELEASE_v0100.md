# 0.10.0 — 실제 순천 적용과 근거 중심 업무 흐름

작성일: 2026-10-23. 아래 내용은 구현·자료 검증의 범위이며, 지자체 현장 운영 실증이나 대회 심사점수 인증이 아니다.

## 1. 사용자에게 달라지는 점

상단 **다른 지역도 적용해보기 → 순천 적용해보기**에서 순천의 실제 자료로 이동한다. 직접 주소는 `/?region=suncheon`이며 서구는 `/?region=seogu`다. 지역 전환은 새 화면을 열어 지도 상태·질문 결과가 섞이지 않게 하며, 공간 작업과 업무효과 기록은 지역별로 보관한다.

공공공간 운영안 검토를 읍면동 목록 위에 배치했다. 상단 날씨 옆 질문창은 유지했고, 순천에서도 사용할 수 있다. 주요 목록·설명과 질문·비교 본문의 글자를 키웠다. 작은 화면의 비교표는 자체 가로 스크롤을 사용한다.

### 처음 써 보는 순서

1. 상단 **다른 지역도 적용해보기**에서 순천을 연다.
2. 질문창에 **“장천동에서 토요일 10시부터 12시까지 주민 모임을 할 공간을 찾아줘”**라고 입력한다.
3. 수록 후보·출처·미확인 사항을 읽고 **이 조건으로 비교 준비**를 누른다.
4. 확인 전 초안에서 토요일·10:00·12:00을 확인한다. **조건 확인·적용**을 누른다.
5. 실제 수록 공간을 선택한다. 확인하지 않은 운영 상태는 미확인으로 두고, 실제 확인한 정보만 현황에 기록한다.
6. 개방 요일·시간이나 운영비를 바꾸는 안을 가정으로 작성하고 같은 조건으로 비교한다.
7. AI 검토를 열어 중요한 차이와 후속 확인업무를 읽는다. 숫자는 서버가 다시 계산한 값이며 예약 가능·사업 승인 판정이 아니다.
8. 비교와 설명을 저장하고 보고서를 받는다. 저장본을 다시 열면 당시 설명을 복원한다.

요청에 요일·시간이 없으면 기본값을 몰래 넣지 않는다. `주말`, 여러 시간대, `저녁 7~9`처럼 해석이 갈릴 수 있는 표현은 확인을 요구한다. 인원·예산은 확정 운영 현황이나 검증된 수요로 바꾸지 않는다.

## 2. 두 지역의 실제 자료

| 항목 | 서구 | 순천 |
| --- | --- | --- |
| 실제 행정경계 | 18개 행정동 | 24개 읍·면·동 |
| 수록 공공공간 | 58개 | 67개 |
| 순천 원자료 통합 | 해당 없음 | 시간·요금 조건별 78행을 67공간으로 통합 |
| 순천 공간자료 범위 | 해당 없음 | 8개 읍·면·동, 서로 다른 대표좌표 20곳 |
| 공통 기능 | 질문, 공간 선택, 현장 확인, 변경안, 계산, AI 검토, 보관·보고서, 업무효과 기록 | 동일 |
| 추가 자료 | 기존 서구 환경·재난·생활자료와 검토 기능 | 확인된 공공공간 자료부터 적용 |

순천 경계 기준일은 2026-07-01, 공간자료 기준일은 2026-10-10이다. 공간 개수는 건물 수가 아니다. 공개 자료에 수록되지 않은 읍면동에 실제 시설이 없다는 뜻도 아니다. 같은 공간에 서로 다른 시간·요금 원문이 있으면 모두 보존한다. 원자료, 위치 대응, 이용조건, 수집·변환 이력은 [순천 자료 설명](SUNCHEON_DATA.md)에 기록한다.

실제 자료팩 두 개를 공통 코드에 적용한 것은 확산 가능성의 기술 증빙이다. 순천시가 도입하거나 공무원이 업무 성과를 실증했다는 뜻은 아니다. 새 지역은 [타 지자체 적용 안내](REGION_ADOPTION.md)에 따라 경계·공간·지역코드·출처를 검증하고 등록한다.

## 3. AI가 맡는 일과 서버가 확인하는 일

### 일반 질문

서구의 기존 공간도구 조회와 요약은 유지했다. 숫자 검사에서 한 자리 수 누락을 보완하고, 질문에 들어 있는 예산·인원 등 입력 가정을 확인된 수치와 분리한다. 자유문장의 모든 의미를 증명하는 검사는 아니다.

순천 질문은 현재 지역의 공개 공간으로 조회 범위를 한정한다. AI는 실제 후보 ID와 후속 확인사항 코드를 선택한다. 서버가 ID·허용 코드·지역을 검증하고 개수·시설명·출처 문장을 구성한다. 모르는 공간이나 다른 지역의 ID를 반환하면 AI 결과를 쓰지 않고 규칙 조회를 제공한다.

### 운영 대안 비교

AI는 대안 ID·공간 ID·지표 참조, 조건 차이와 후속 확인업무를 고른다. 서버는 다음을 검사한 뒤 계산값으로 문장을 만든다.

- 실제로 존재하는 대안·선택 공간·지표인지
- 현재 확인값과 입력 가정이 구분됐는지
- 미확인인 현재값을 바탕으로 개선량을 주장하지 않는지
- 설명한 원인이 실제 조건 차이에 해당하는지

AI의 판단 순서·근거 선택을 사용하되, 숫자 계산을 생성형 모델에 맡기지 않는다. AI 연결 실패·한도·형식 오류가 있어도 비교 계산은 계속 쓸 수 있고 화면에 응답 방식을 표시한다.

### 지역별 날씨

상단 날씨도 현재 지역의 좌표로 요청한다. 기존 기상청 키를 공통으로 사용하며, 서버는 등록 지역의 좌표 범위를 검사한다. 지역별 캐시를 분리하고 응답 지역·격자가 요청과 다르면 표시하지 않는다. API 미수신 상태를 다른 지역의 날씨로 대신하지 않는다.

## 4. 기록의 재현과 변경 확인

새 현장 확인은 확인 당시의 공간 원자료 지문과 연결된다. 원자료의 이름·주소·좌표·소속 동·운영시간·출처가 바뀌면 **원자료 변경 · 재확인 필요**로 바뀌며 계산에서 미확인으로 처리한다. 구버전 확인기록은 읽을 수 있지만 과거 변경 추적 여부가 다름을 표시한다.

비교 보관에는 계산 결과뿐 아니라 당시 AI 설명·모델·응답 방식·생성시각·근거 식별값을 함께 넣는다. 복원은 모델을 다시 호출하지 않는다. JSON 가져오기는 비교 연결과 구조화 근거를 다시 확인한다. 지문은 변경 탐지 수단이며 인증서명이나 공식 승인 증명은 아니다.

같은 탭의 새로고침에는 지역별 미저장 초안을 복구한다. 복구한 현황 입력을 확인 완료 기록으로 자동 승격하지 않는다. 브라우저 저장 실패는 알리고 작성한 초안을 유지한다. 장기 보관·다른 기기 이동에는 JSON 백업을 사용한다.

## 5. 검증 범위

소스 회귀검사, 실제 두 지역 데이터팩 검증, 빌드·로컬 HTTP 검사, 브라우저 업무 흐름을 확인한다. 실행 가능한 검사는 다음과 같다.

```sh
npm run check
npm test
node scripts/validate-region.mjs --profile seogu
node scripts/validate-region.mjs --profile suncheon
npm run build
node scripts/audit-release.mjs
```

핵심 회귀검사는 지역 요청 허용 목록, 지역 간 공간 ID 혼입 차단, 미수록과 실제 부재 구분, 질문 시간 전달, 초안 복구, 과거 설명 보존, 원자료 변경 시 재확인, AI 근거 참조 조작 거부를 포함한다.

2026-10-23 배포 전 검증 결과:

| 검증 | 결과 | 범위 |
| --- | --- | --- |
| JavaScript 구문 검사 | 통과 | 실행 소스 전체 |
| 자동 회귀 검사 | 737 / 737 통과 | 실제 지역 자료·모델 계산·실패 처리·가짜 제공기관 응답을 사용한 API 계약 검사 |
| 배포 파일 검사 | 24 / 24 통과 | 두 지역 자료팩과 실행 파일 포함 여부 |
| 로컬 HTTP 검사 | 61 / 61 통과 | 빌드 파일과 API 응답·지역 거절 처리 |
| 실제 Chromium 업무 흐름 | 98 / 98 통과 | 1366×768 및 360×800에서 지역 전환→질문→조건 확인→가상 현황→대안 비교→설명 보관→보고서→복원 |

브라우저 검증은 키 없는 로컬 서버와 경계도에서 실행했으며 외부 지도·API는 차단했다. 입력 현황은 가상시험용이라고 명시했고, 실제 공무원 실증·예약 가능 확인·배포 AI 연결 성공으로 집계하지 않는다. 주요 업무 글씨 14px 이상, 질문·폼 입력 16px, 화면 가로 넘침 없음, 클라이언트 예외 없음도 확인했다. 배포판의 실제 외부 연결은 별도로 확인한다.

## 6. 높은 평가를 위해 남는 증빙

개발자가 자동 검사로 만들 수 있는 증빙과 실제 행정 담당자가 수행해야 하는 증빙은 구분한다. 실제 사용자 없이 시간 절감률·오류 감소율·만족도나 98점 달성을 기입하지 않는다.

- [업무효과 측정 절차](PILOT_PROTOCOL.md)에 따라 같은 과제·자료·완료기준으로 기존 방식과 앱을 비교한다. 실제 시간·오류·출처누락·익명 결과물을 보관한다.
- 처음 쓰는 담당자가 안내 없이 질문→비교→보고서를 완료할 수 있는지 관찰한다. 막힌 위치와 수정 전후를 기록한다.
- 대회 최종 제출물에서는 기능 수보다 대표 업무 한 흐름, 실제 순천 전환, 출처와 미확인 처리, 원자료 변경 후 재검토, 당시 보고서 복원을 보여 준다.
- 실제 업무효과와 도입 범위가 검증되기 전에는 완성형 전 도시 실시간 트윈이나 정밀 예측 성능으로 표현하지 않는다. 현재는 공공공간 운영 조건의 확인·가정·재계산을 연결한 행정 의사결정 지원 시제품이다.
