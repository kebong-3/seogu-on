# 받은 파일함 사용법 — 공공데이터 CSV를 지도 자료로 바꾸기

개발 지식 없이 따라 할 수 있게 적었습니다. 하는 일은 세 가지뿐입니다.

1. 공공데이터포털에서 CSV 파일을 내려받는다.
2. 프로젝트의 `data-inbox/` 폴더에 넣는다. (파일 이름은 바꾸지 않아도 됩니다)
3. 프로젝트 폴더에서 명령 한 줄을 실행한다.

```
node scripts/data/ingest.mjs
```

저장하기 전에 결과만 보고 싶으면 뒤에 `--dry-run` 을 붙입니다. 아무 파일도 바뀌지 않습니다.

```
node scripts/data/ingest.mjs --dry-run
```

## 1. 내려받을 파일 (위에서부터 순서대로)

각 주소를 열고 **「파일데이터 다운로드(CSV)」** 또는 **「CSV 다운로드」** 단추를 누릅니다. 표준데이터 페이지에 지역을 고르는 칸이 있으면 전국 파일을 그대로 받아도 되고, 서구·광주만 골라 받아도 됩니다(도구가 서구 경계 안의 점만 골라냅니다). 엑셀(XLSX)·JSON·XML이 아니라 **CSV**로 받으세요.

「연결 확인」 칸의 뜻
- **확인됨**: 저장소에 있는 실제 원본 파일로 열 이름을 확인했습니다.
- **미검증**: 표준데이터 명세를 기억에 의존해 연결했습니다. 실제 파일의 열 이름이 다르면 도구가 그 파일의 제목행을 그대로 보여 주며 멈춥니다(잘못 넣지 않습니다).

## 2. 실행 결과 읽는 법

실행하면 자료마다 아래와 같은 묶음이 나옵니다.

```
■ 전국무더위쉼터표준데이터  [heat-shelter]
  파일: 전국무더위쉼터표준데이터.csv (euc-kr)
  판별 근거: 제목행 · 기억에 의존한 연결(실제 파일 미검증)
  원본 55,000행 → 서구 안 120개 채택 / 54,880행 제외
    - 다른 지역(서구 경계 밖) 행: 54,870행
    - 좌표 없음: 6행
    - 주소·자료는 서구인데 좌표가 서구 경계 밖: 2행
    - 경도·위도가 뒤바뀐 행을 바로잡음: 1행
  자료 기준일: 2026-06-30 (데이터기준일자 열)
  읽은 열: name←쉼터명칭, lat←위도, lon←경도, …
  쓰지 않은 열: …
  저장 위치: public/data/city/official/heat-shelter.geojson  (이전 0개 → 이번 120개)
  결과: 저장 완료
```
(위 숫자는 설명을 위한 예시이며 실제 값이 아닙니다.)

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 서구 안 N개 채택 | 좌표가 18개 행정동 경계 안에 있는 행의 수. **서구 시설 전체 수가 아닙니다.** | 없음 |
| 다른 지역 행 | 전국 파일에서 서구 밖 지역의 행 | 정상 |
| 좌표 없음 | 위도·경도가 빈 행. 지도에 넣지 않았습니다. | 「서구 자료인데 좌표가 없어…」 줄의 숫자가 크면 원문 기관에 좌표 보완을 요청 |
| 주소·자료는 서구인데 좌표가 서구 경계 밖 | 좌표 오류일 가능성. 고치지 않고 제외했습니다. | 「제외 예시」의 행 번호를 원본에서 확인 |
| 경도·위도가 뒤바뀐 행을 바로잡음 | 경도 칸에 위도가, 위도 칸에 경도가 들어 있어 맞바꾼 행. 한국의 경도(124~132)와 위도(33~39)는 범위가 겹치지 않아 확실할 때만 바꿉니다. | 없음 |
| 좌표가 완전히 같은 점 묶음 | 같은 자리에 여러 행. 지우지 않았습니다. | 개수를 시설 수로 읽지 않기 |
| 읽은 열 / 쓰지 않은 열 | 원본의 어느 열을 무엇으로 읽었는지 | **미검증 자료는 처음 한 번 꼭 확인.** 이름·주소가 엉뚱한 열에서 왔다면 알려 주세요 |
| 결과: 저장 완료 | 파일을 새로 썼고, 자료 현황표와 품질 점검표도 다시 만들었습니다. | 화면에서 확인 후 커밋 |
| 결과: 변경 없음 | 이미 같은 내용입니다. 여러 번 실행해도 안전합니다. | 없음 |
| 결과: 확인 필요(저장하지 않음) | 이전보다 개수가 절반 아래로 줄었습니다. 일부만 받은 파일일 수 있어 덮어쓰지 않았습니다. | 파일이 맞다면 `node scripts/data/ingest.mjs --force` |
| 결과: 반영 없음 | 서구 안의 좌표 행이 하나도 없어 기존 파일을 그대로 두었습니다. | 파일을 잘못 받았는지 확인 |
| ✗ 어떤 자료인지 알아보지 못했습니다 | 제목행이 연결표와 맞지 않습니다. 아무것도 저장하지 않았습니다. | 화면에 나온 「이 파일의 제목행」을 복사해 전달하거나, 파일 이름 앞에 `[자료키]` 를 붙여 다시 실행 (예: `[toilet]파일.csv`) |

자료키 목록은 `node scripts/data/ingest.mjs --list` 로 볼 수 있습니다.

## 3. 자주 생기는 일

- **글자가 깨져 보일까 걱정될 때**: 공공기관 CSV는 대부분 CP949(EUC-KR)라는 옛 한글 방식입니다. 도구가 자동으로 알아보고 읽으며, 결과의 「파일: … (euc-kr)」로 표시합니다. 엑셀로 열어 다시 저장할 필요가 없습니다.
- **기준일을 확인하지 못했다고 나올 때**: 파일 안에 「데이터기준일자」 열이 없고 파일 이름에도 날짜가 없는 경우입니다. 포털 페이지에 적힌 기준일을 확인해 파일 이름 끝에 `_20260106` 처럼 붙이고 다시 실행하세요. 날짜를 지어내지 않습니다.
- **같은 자료의 파일이 여러 개일 때**: 함께 넣어도 됩니다. 같은 관리번호(또는 같은 이름+주소)는 기준일이 최근인 행 하나만 남깁니다.
- **다 쓴 CSV**: `data-inbox/` 에 그대로 두어도 되고 지워도 됩니다. 원본 CSV는 저장소에 올리지 않습니다.
- **엑셀 파일(XLSX)만 제공되는 자료**: 엑셀에서 「다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)」로 저장해 넣으세요.

## 4. 이 도구가 지키는 원칙

- 좌표를 만들어 넣지 않습니다. 주소만 있는 행은 지도에 올리지 않고 개수만 알려 줍니다.
- 담당자 이름, 휴대전화 번호 같은 개인 정보 열은 읽지 않습니다. 전화번호는 기관 대표번호(지역번호·대표번호 형식)만 남깁니다.
- 공식 파일은 OpenStreetMap에서 온 기존 층과 **한 파일에 섞지 않습니다.** 같은 공식 자료의 이전 공개본(공원·주차장·도서관·학교 위치, 서구 그늘막·쿨링포그·침수기록)만 최신본으로 바꿉니다. 나머지는 「공식 표준자료」라는 별도 층으로 옆에 둡니다.
- 모든 시설에 출처·자료 기준일·내려받은 시각을 적습니다. 「현장 확인」이라고 표시하는 자료는 없습니다.
- 자료를 받지 않은 층은 0개가 아니라 「자료 연결 필요」로 표시됩니다.
