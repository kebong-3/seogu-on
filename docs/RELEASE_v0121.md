# 0.12.1 — 실제 사용 중 발견한 시설 분류·좌표 오류 보완

## 이번에 고친 문제

- 유치원·지역아동센터·공동육아나눔터 등을 묻는 질문이 어린이집만 수록된 생활지도로 넘어가던 문제를 수정했다. 별도 시설 분류를 사용하는 기존 질문 흐름으로 보내며, 자료가 없으면 어린이집 목록으로 대신 답하지 않는다.
- 광주서구청어린이집의 원문 좌표가 같은 주소의 별도 공식 공개자료와 2,472m 어긋나는 것을 확인했다. 해당 시설 ID와 문제 좌표가 모두 일치하는 기록을 공간 수록·계산에서 제외했다. 비교자료의 좌표로 자동 대체하지 않는다.
- 원문 좌표·행 번호·수집시각·해시와 비교 근거를 제외 기록에 남겼다. 원문 좌표가 바뀌면 일반 검증을 다시 적용한다. 서구 어린이집의 공간 수록은 122개이며 순천 151개 자료는 변경하지 않았다.
- 생활지도 집계 제목을 ‘공개자료 수록 위치’로 바꿔 현장 위치 검수가 완료된 시설 수라는 오해를 줄였다. 실제 시설을 후보로 선택했을 때도 자연스러운 다음 행동을 안내한다.
- 이전 버전의 저장 보기 조건을 계속 읽으면서 새 내보내기와 화면 식별자를 0.12.1로 갱신했다.

## 실제 배포 화면에서 확인한 업무 흐름

- 서구 어린이집 검색 → 선택 시설의 이름·좌표를 후보 A로 전달 → 주변자료 비교
- 현재 계산의 근거와 후속 업무를 고르는 AI 메모의 실제 응답
- 메뉴에서 순천으로 전환 후 해당 지역의 자료로 재계산
- 순천의 직선거리 150m·그늘막 후보 3곳: 고유좌표 기준 241/651 → 280/651
- 첫 후보 제외 후: 263/651로 재계산, 새로 조건에 들어오는 위치 39곳 → 22곳

위 수치는 같은 공개 위치자료를 사용하는 거리조건 비교이며 실제 그늘·이용자 수·안전도·사업 효과를 뜻하지 않는다. 좌표 불일치 사례를 발견해 수정한 사실도 전체 자료의 현장 정확성을 보장하지 않는다.

HTML 검토서와 CSV의 브라우저 다운로드는 이벤트 이후 이 클라우드 실행환경에서 파일 전달에 실패하여, 파일 저장 완료까지는 확인하지 못했다. 계산 화면·AI 응답 확인과 다운로드 완료 검증을 구분한다.

## 검증 방법

`node scripts/check.mjs`, `node --test --test-isolation=none tests/*.test.mjs`, `node scripts/build.mjs`를 실행한다. 수집기 회귀검증은 문제 있는 ID·좌표 쌍만 제외하는지, 원문 좌표가 바뀌거나 다른 시설이 같은 좌표를 쓸 때 과도하게 제외하지 않는지를 확인한다. 빌드는 두 지역의 자료 해시와 모든 등록 비교 업무를 다시 검증한다.

최종 검증 기록: 전체 774개 중 최초 실행에서 771개가 통과했다. 남은 항목은 후보 안내 문구 1건, 122개로 갱신이 필요한 자료 집계표 1건, 실행환경의 하위 Node 프로세스 권한 1건이었다. 문구와 생성 집계표를 수정한 뒤 관련 검사 13개가 모두 통과했고, 권한이 필요한 로컬 수집기 검사도 별도로 실행해 10개가 모두 통과했다. 실패 항목을 무시하거나 검사를 제거하지 않았다.
