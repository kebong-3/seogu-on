# 0.11.0 — 결과부터 보여 주는 행정 업무형 공간 비교

## 문제와 변경

종전의 공공공간 운영시간 비교는 현장 확인 정보를 먼저 입력해야 결과가 나왔다. 최초 효용이 낮다는 사용자의 피드백에 따라 실제 공무원의 시설 배치·현장점검·후보지 비교를 전면에 배치했다.

- 첫 화면에 현재 자료로 계산한 공백과 추가 후보의 변화 표시
- 공통 엔진으로 실제 시설 추가·위치 이동·중단의 전후 재계산
- 고유 좌표와 원문 기록 수 구분, 중복 후보의 기여도 표시
- 자연어 조건 해석과 서버 계산 근거를 사용하는 AI 검토메모
- 기존 자료와 공식 공개자료 4종/지역 파일 5개 결합
- 지역별 자료·요청·좌표·출처 해시 검증, 같은 12개 서버리스 함수 안에 새 경로 배치
- 읽을 수 있는 입력·결과·후보 카드, 반경선, HTML 검토서와 전체 CSV
- 공공공간 운영시간 검토 등 기존 도구 유지

새 실시간 API 다섯 개를 연결했다는 의미가 아니다. 공공데이터포털의 실제 공개 JSON 원문을 수집·검증하여 배포한 자료다. 원본·중복 제외 근거·라이선스·제공기관별 수록범위는 `DECISION_DATA_SOURCES.md`에 기록한다. 수집기는 `scripts/data/collect-decision-sources.mjs`이다.

## 계산 검증

- `node --test --test-isolation=none tests/*.test.mjs`: 759개 통과, 실패 0
- 새 공유모델: 반경·인접 동 시설·중복 후보·기존시설 제외·추가/손실·지역/좌표·자료 미상·횡단보도 원문 상태 검증
- 새 API: 명시 조건 우선, 메모 작성 시 조건 보존, 다른 지역·복수 동 질문 거부, 같은 출처 요청 제한, 모델 근거 검증
- 실제 데이터 게이트: 서구 8개 자료/4업무, 순천 5개 자료/3업무
- 후보 순서가 바뀌어도 총결과·단독 제외효과 유지, 동일 좌표로 시설 복원 시 기준 상태 복구
- 기존 서구 데이터 감사는 저장된 품질보고서와 동일, 새 지역 자료는 각자의 경계로 별도 검증
- 로컬 HTTP에서 두 지역 초기 조회·후보지 조회·화면 모듈 응답 확인

빌드 시 `validateDecisionPacks()`를 실행하며 자료 해시와 검증한 지역별 계산 요약을 `data/release.json`에 기록한다. 배포 식별자는 `0.11.0`이다.

## 실제 사용에서 남는 범위

직선거리 조건은 분석 가정이다. 시설 설치 가능성, 실제 그늘, 개방시간, 보행 경로, 수요·인구·비용·정책 효과는 산정하지 않는다. 서구 정류장은 OSM 부분 자료이며 누락을 시설 부재로 처리하지 않는다. 횡단보도 원문의 미설치 표기를 위험·위법 판정으로 바꾸지 않는다. 실행 시점의 외부 지도와 AI 제공기관 응답은 별도 상태로 표시한다.
