# 공공공간 활용 화면

이 화면은 실제 공공 개방 공간을 선택하고, 현장에서 확인한 운영조건과 변경안을 같은 요일·시간으로 비교하는 업무 흐름이다. 공공자료의 회의실·강당 같은 공간이 단위이며, 건물 수나 주민 수로 읽지 않는다. 별도의 수요 예측값이나 가상의 사업효과 점수를 만들지 않는다.

## 담당자가 사용하는 순서

상단 질문창에 “장천동에서 토요일 10시부터 12시까지 주민 모임을 열 공간을 검토해줘”처럼 입력하고 **이 조건으로 비교 준비**를 선택해도 아래 흐름을 시작할 수 있다. 질문에 명시한 요일·시간은 **확인 전 초안**으로 표시하며 담당자가 확인해야 계산조건에 반영한다. `주말`, 여러 요일, 여러 시간대나 날짜가 넘어가는 심야 일정은 임의로 확정하지 않는다. 질문의 참여 인원은 요청 맥락으로만 보여 주며 정원 검증이나 수용 인원 계산에 사용하지 않는다. 직접 메뉴를 열었을 때에도 요일·시간을 자동으로 월요일 저녁으로 채우지 않는다.

1. **공공공간 활용 → 공간 선택**: 지도 지점 또는 공간명·주소 검색 결과에서 한 번에 10개까지 고른다. 지도 구역을 바꿔도 선택 목록은 유지하며, 현재 구역 밖 공간을 포함하면 이를 표시한다.
2. **현황·변경안 → 현재 운영조건 확인**: 공개 원자료의 운영시간 문장, 출처, 기준일을 먼저 읽는다. 확인한 운영 여부·요일·시간·확인일·근거를 입력하고 저장한다. 운영조건을 확인하지 못했으면 현재 상태를 임의로 채우지 않고 변경안부터 작성할 수 있다. 유효기간이 지난 확인값은 모델에서 미확인으로 처리한다.
3. **변경안 작성**: 선택한 실제 공간의 운영조건과 추가 연간 운영비 가정을 입력한다. 비용은 만원/년이며 모르면 비운다. 같은 대안을 열고 다른 공간을 선택하면 여러 공간의 변경을 한 대안에 넣을 수 있다. 저장 대안은 최대 3개다.
4. **비교·기록**: 검토 요일과 이용 시작·종료 시각, 비교할 대안을 정하고 계산한다. 현재 확인값과 변경 가정은 다른 열에 표시한다. 요청 시간 전체의 개방 조건을 충족하는 공간, 미확인 공간, 조건 불일치 공간, 겹치는 개방시간 합계, 추가 연간 운영비를 비교한다. 비교할 대안의 공간이 선택 목록에 빠져 있으면 포함하거나 해당 대안의 체크를 해제해야 한다. 체크 해제는 저장한 대안을 삭제하지 않는다.
5. **AI로 차이·협의사항 설명**: 버튼을 누를 때만 선택 공간과 확인 조건·변경안을 서버로 보낸다. 서버가 배포 지역의 원자료로 다시 계산한 뒤 설명한다. AI는 실제 계산에 있는 대안·공간·지표와 확인사항을 선택하고, 표시할 수치와 근거 문장은 검증된 참조로 구성한다. 화면의 계산과 서버 계산이 다르면 설명을 보류한다. 계산표가 근거이며 AI 문장은 검토 보조다. AI를 사용할 수 없을 때 계산 근거 요약과 AI 설명을 구분한다. 첫 결과에는 확인한 계산·핵심 미확인·다음 행동과 출처 기준일을 먼저 표시하고 공간별 상세 근거는 펼쳐 본다.
6. **비교 결과 보관 / 검토보고서 HTML**: 저장본은 최대 20개다. 당시 조건·수치·공간별 확인 근거·출처와 완료된 당시 설명을 함께 보존한다. AI 응답이면 모델명, 생성시각, 계산 지문과 근거 식별값도 남긴다. 이후 현황을 바꾸거나 모델을 교체해도 과거 보고서를 최신 AI로 다시 쓰지 않는다. 설명 없이 저장한 이전 결과는 설명이 없었다고 표시한다. 저장 당시 결과를 보는 동안 현재 입력은 별도로 유지하고 ‘현재 작성 중인 검토로 돌아가기’로 이어간다. HTML은 브라우저 인쇄로 종이 또는 PDF로 저장할 수 있다.
7. **다시 현장 확인**: 실제 운영조건이 바뀌거나 재확인이 필요하면 현황을 다시 기록한다. 이전 값과 새 값의 이력이 남고, 동일한 조건에서 다시 계산한다. 최근 두 저장본의 차이는 기록상 변화이며 정책효과 실측값이 아니다.

위 표는 활용 방식이다. 특정 프로그램의 적법성·수요·성과를 이 계산으로 확정하지 않는다.

## 자료 구분과 저장

- **공개 원자료**: 현재 배포 지역의 `facilitiesUrl`에서 가져온 실제 공간과 출처다. 원자료 운영시간 문장을 자동으로 확정된 운영조건으로 바꾸지 않는다.
- **사용자 현장 확인**: 확인일과 근거를 갖춘 사용자 기록이다. 기관의 공식 운영 승인이나 예약 현황을 의미하지 않는다. 재확인 기한 또는 모델의 90일 기준이 지나거나, 확인 당시와 현재 원자료의 주요 속성이 달라지면 확인이 필요하다. 새 기록은 공간의 이름·위치·원자료 운영시간·출처 지문을 함께 보관한다. 이전 버전의 지문 없는 기록은 호환하되 원자료 변경 추적이 불가능하다고 표시한다.
- **사용자 가정**: 변경안의 운영조건·추가 연간 운영비다. 저장한다고 실제 시설 운영이 바뀌지 않는다.
- **보관 장소**: 지역별 브라우저 `localStorage`다. 기관 공동 데이터베이스, 사용자 인증, 권한, 전자결재는 구현 범위에 없다.
- **JSON 백업·가져오기**: 같은 지역의 2MiB 이하 검증된 백업만 받는다. 합치기 전에 건수를 보여 주며, 더 최근에 확인한 현황과 양쪽 변경 이력을 유지한다. 같은 ID의 서로 다른 대안·저장본이나 제한 초과는 자동으로 덮어쓰지 않고 거부한다. 기존 저장소를 읽지 못한 경우 원본 백업을 제공하고 기록 변경을 막는다.
- **입력 초안**: 저장 전 현황·변경안·질문 조건과 선택 목록을 지역별 `sessionStorage`에 보관해 같은 탭 새로고침에서 복구한다. 복구해도 확인한 현황이나 저장된 변경안으로 자동 승격하지 않는다. 탭 종료 후 복구·다른 기기 동기화를 보장하지 않는다. 저장소 쓰기 뒤 읽기로 보존을 확인하며, 자동 복구가 막히면 새로고침 전에 저장 또는 복사하라는 안내와 탭 이탈 확인을 제공한다. 확인 기록 저장이 실패해도 입력 초안은 지우지 않는다.

## 앱 통합 계약

`src/city/space-twin.js`는 `installSpaceTwin(api, options)`를 내보낸다.

```js
const spaceTwin = installSpaceTwin(api, {
  getRegion: () => state.regionProfile,
  loadAssets: profile => fetchJSON(profile.facilitiesUrl),
});
```

필요한 API는 `state`, `show`, `label`, `toast`, `drawData`, `send`와 `loadAssets`를 생략하는 경우의 `fetchJSON`이다. `state`에는 `view`, `dong`, `scope`, `enabled`, `entries`, `regionProfile`이 있다. `state.regionProfile`의 `id`, `name`, `facilityLayerId`, `facilitiesUrl`, `capabilities`를 사용한다.

- 기본 진입 동작: `data-action="space-twin"`
- 질문 연계: `api.run('space-from-question', {question, regionId, dongId})`. 현재 지역과 다른 `regionId`는 거부한다. 지도에서 이미 적용한 지역·구역과 질문의 명시 조건을 확인 초안으로 표시한다.
- 초안 확인: `space-apply-query-draft`; 직접 입력 전환: `space-dismiss-query-draft`. 확인 전 초안을 둔 채 계산할 수 없다.
- 실제 시설 상세에서 연결: `data-action="space-twin-from-feature" data-id="원자료 ID"`
- 패널 식별값: `space-twin`
- 지도 임시 레이어: `space-twin-candidates`. 다른 레이어의 켜짐 상태는 유지한다.
- 지도 이벤트: 기존 상세 선택 처리 전에 `if (spaceTwin.onEvent(message)) return;`을 호출한다.
- 구역 변경: 기존 scope 갱신 후 `spaceTwin.scopeChanged()`.
- 해제: `spaceTwin.destroy()`로 이벤트·자체 레이어를 제거한다.
- 스타일: `src/city/space-twin.css`를 앱에서 불러온다. 앱의 배경·본문·보조문자 테마 변수를 사용하고 본문·표·보조문자 14px 이상, 입력 글자 16px, 필드 높이 44px, 키보드 포커스 표시를 적용한다. 여러 대안 표는 가로 스크롤로 읽는다.

공간 ID는 모델에서 `profile.facilityLayerId::원자료 ID`로 생성한다. 지역은 별도 `regionId`로 검증한다. 타 지역을 같은 지역으로 위장해 연결하지 않는다.

AI 요청은 `POST /api/space-review`에 `{regionId, assetIds, observations, query, scenarios}`를 보낸다. `observations`에는 선택한 공간만, `scenarios`에는 비교에 포함한 대안만 담는다. 응답의 `{ok, mode, answer, notice, model, comparison, comparisonFingerprint, computedAt, evidenceId, structured}`를 사용한다. `assetFingerprint`, `query`, `baseline`, `alternatives`가 화면 계산과 동일해야 설명을 표시하며 서버의 생성시각·기록 버전은 비교에서 제외한다. `saveSnapshot(workspace, comparison, {ai})`는 계산과 연결된 완료 응답의 필요한 필드만 검증해 보관한다. 복원 UI와 보고서는 `snapshot.ai`를 그대로 사용한다.

상단 질문은 `POST /api/ask`에 `regionId`를 보내며 순천에서도 활성화된다. 순천은 지역 공공공간 조회·후보 선택·조건 비교를 지원하며, 서구 전용 마을 검토노트 링크는 노출하지 않는다. 질문 답변 첫 화면은 수록자료로 확인한 사실·핵심 미확인·다음 행동과 출처/기준일을 보여 준다. 긴 협의 안내와 상세 조회 근거는 접을 수 있으며 복사·메모 저장에는 전체 내용이 들어간다. 대기 중에는 실제로 응답을 기다린다는 상태만 표시하고, 실패 시 같은 질문 재시도 또는 조건 비교로 이어간다.

## 실제 브라우저 통합 검증

`tests/region-workflow-ui.mjs`는 실행 중인 키 없는 로컬 개발 서버를 대상으로 Chromium의 1366×768과 360×800 화면에서 실제 사용자 동작을 수행한다. 서구에서 지역 메뉴로 순천을 선택하고, 장천동 토요일 10–12 질문을 보낸 뒤 조건 초안 확인, 공간 선택, 가상 확인값 입력, 새로고침 복구, 운영 대안 두 개 비교, 서버의 규칙 기반 설명, 설명을 포함한 스냅샷, HTML 보고서 다운로드, 과거 결과 재발행, 서구·순천 기록 분리를 확인한다. 외부 지도·API는 차단하고 경계도 모드만 사용한다. 모든 현장값은 가상시험임을 표시하며 실제 사용자 실증이나 외부 API 성공률을 측정하지 않는다.

```sh
SEOON_UI_BASE=http://127.0.0.1:4173 SEOON_UI_OUT=/tmp/seogu-v0100-ui node tests/region-workflow-ui.mjs
```

시험 환경에 Playwright와 Chromium, 한글 글꼴이 필요하다. Chromium 경로는 `SEOON_CHROMIUM`, 임시 글꼴 설정은 `SEOON_UI_FONTCONFIG`로 지정할 수 있다. 결과 JSON·화면 캡처·가상시험 보고서는 출력 폴더에 남긴다. 자동 점검은 질문·비교 본문 14px 이상, 입력 글자 16px, 화면 가로 넘침 없음, 조건 확인 버튼의 첫 화면 노출도 확인한다.
