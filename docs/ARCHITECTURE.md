# 구현 구조와 확장 지점

## 웹 전용 구성

이번 버전은 Unity 프로젝트나 Unity Web 빌드가 아닙니다. **표준 ES Modules + CSS + MapLibre GL JS + 선택적인 VWorld SDK + Vercel Node.js Functions**입니다. 복잡한 빌드 의존성 없이 업로드·수정할 수 있도록 React/Vite 대신 가벼운 모듈형 JavaScript를 선택했습니다.

`npm run build`는 `index.html`, `src`, `public`을 배포 폴더 `dist`로 복사합니다. 실제 API 키가 담긴 환경변수 파일, 서버 코드, 문서는 정적 `dist`로 복사하지 않습니다. 루트 `api/` 함수와 `server/` 공통 코드는 Vercel의 Node.js 경로에서 실행됩니다.

## 연결 흐름

```text
등록된 공개 API 또는 검수된 GeoJSON
    ↓ 고정된 주소/명세·인증·범위 제한
시설 표준 형식(Point / id / 분류 / 출처 / 기준일 / monthly)
    ↓ 좌표·날짜·중복·결측 검사
공통 상태: 자료종류, 월, 시설분류, 검색어, 반경, 선택시설
    ├─ 지도 어댑터(MapLibre / VWorld / 가상 디자인)
    ├─ 집계·동일대상 전월비교·사업 대표점 근접 계산
    └─ 근거 카드·표·차트·시간축·검토표
```

지도 카메라 이동은 현재 시설 집계조건을 바꾸지 않습니다. 화면에 보이는 범위만 집계하는 기능은 없습니다. 반경 조건이나 분류·검색·기간을 변경해야 집계가 바뀝니다. 지도상 표시 수 제한과 표의 건수도 구분합니다.

## 학습이 필요하지 않은 이유

시설 API의 좌표와 속성은 AI의 학습데이터가 아니라 지도 위에 배치할 **운영 데이터**입니다. 지도 SDK를 사용하는 방법은 개발자가 문서를 참고하여 구현합니다. 건물 도형·높이·지형 타일을 읽어 그리는 기능은 지도 엔진이 담당합니다. AI가 건물의 정확한 형상을 추정해서 채우도록 하지 않았습니다.

향후 LLM을 추가한다면 자연어를 허용된 조회함수 호출로 변환하는 수준부터 시작하는 것을 권장합니다. 월별 합계나 거리는 계산 함수가 산출하고, AI는 반환된 결과와 출처를 설명하도록 분리하면 됩니다. 현재는 AI API 호출이 없으며 모델 학습도 수행하지 않았습니다.

## 지도 어댑터

`src/map.js`의 CityMap이 `start`, `update`, `flyTo`, `set3D`, `setBoundary`, `screenshot`, `destroy`를 제공합니다. 공통 시설자료와 상태를 넘기므로 지도 교체가 계산 기능 전체의 재작성으로 이어지지 않게 했습니다.

**MapLibre:** 공개 스타일·OSM 건물 벡터를 읽고 자체 시설·통계기둥·반경·사업선·행정경계 레이어를 추가합니다. 건물 높이는 `render_height`가 있으면 사용하고, 없으면 시각적 기본값을 사용합니다. 이 값은 측량값이 아닙니다.

**VWorld:** SDK를 같은 출처 iframe에서 초기화한 후 Cesium의 별도 CustomDataSource에 자체 시설을 올립니다. 제공기관 원본 데이터소스를 삭제하거나 출처를 감추지 않습니다. iframe 메시지는 동일한 출처·창인지 확인합니다. 브라우저 SDK 호환성과 실제 키 인증은 배포 환경에서 검증해야 합니다.

**디자인 미리보기:** 자체 Canvas 등각투영으로 가상 도시를 그립니다. 사진을 분석해서 실제 지도를 복원한 것이 아닙니다. 외형 확인용이며 `?preview=1` 또는 선택 버튼으로만 작동합니다. 실제 지도 실패를 숨기는 자동 fallback이 아닙니다.

## 상태와 계산

`src/app.js`의 state를 변경하면 `filterFacilities` → `renderInsights/renderLayers/renderTimeline` → `CityMap.update` 순서로 갱신합니다. 자료 업데이트 경쟁을 피하려고 loadToken을 사용합니다. 실제 자료를 읽을 때는 합성자료와 혼합하지 않습니다.

월별 누락은 null/부재로 처리합니다. 전월 대비는 두 월 모두 값이 있는 시설 집합을 사용합니다. 서로 다른 `metricName` 또는 `metricUnit`이 들어오면 합계와 통계기둥을 중단합니다. 같은 이름·단위만으로 자료 정의의 동일성까지 검증되는 것은 아니므로 이용자/이용건수 등 원자료 정의도 담당자가 검수해야 합니다.

## 저장과 공개

환경변수는 서버 설정에만 저장합니다. 브라우저용 SDK 키만 SDK를 동작시키기 위해 전달됩니다. GeoJSON 파일 가져오기, A/B 비교조건은 브라우저 메모리이며 새로고침하면 사라집니다. 테마 선택만 localStorage에 저장합니다. 사진이나 원본 개인정보를 서버로 업로드하는 기능은 없습니다.

`public/data/facilities.geojson`은 배포 파일이므로 모든 방문자가 볼 수 있습니다. 인증·권한별 화면·데이터베이스·조직 공동 편집은 아직 없으며 별도 개발이 필요합니다.

## 확장 우선순위 제안

1. 실제 배포 도메인의 지도·VWorld 인증과 서구 대표 구역 도형을 먼저 확인합니다.
2. 공개시설 한 종류를 좌표·출처·기준일·누락률까지 검수해 연결합니다.
3. 시설 ID와 실제 월별 통계를 연결하고 월별 지표 정의를 맞춥니다.
4. 검수된 행정경계 클리핑, 실제 사업구역 업로드, 보행망 기반 접근성으로 확장합니다.
5. 서버 저장·권한·정기 갱신·모니터링을 갖춘 뒤 제한된 자연어 조회를 추가합니다.

3D Tiles/CityGML/SHP 변환, 사진측량, 실내 모델링, 물리 시뮬레이션, 침수·교통 예측은 현재 범위를 벗어납니다. Unity는 이런 별도 요구가 생길 때 검토할 수 있지만 현재 지도조회·차트·시간축에 필수는 아닙니다.
