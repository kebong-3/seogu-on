# 배포 후 실제 지도·API 검증

이 절차는 제작환경에서 수행 완료한 것이 아닙니다. 유효한 사용자 키, 등록 도메인, WebGL을 사용할 수 있는 브라우저에서 수행하세요.

## A. 배포/지도

1. Production 최신 배포의 커밋에 index.html/src/city/api/city-*가 있는지 확인합니다.
2. `/api/city-config`가0.3.0인지 확인합니다. SDK키가 있다는 플래그만으로 인증 성공을 판정하지 않습니다.
3. 브이월드 SDK준비 표시 후 실제 서구청·치평동·풍암동 건물/지형을 확인합니다. 건물자료가 없거나 지형이 타원체로만 제공되는 경우도 별도로 기록합니다.
4. 서구전체→치평동→공원→풍암동→서구전체를 선택합니다. 비행이 최신 클릭에 맞게 끝나는지, 수동 드래그/Esc로 중단되는지, 지도크게보기 뒤 원래상태가 유지되는지 확인합니다.
5. 데이터면은 경계로 잘리지만 기반건물은 하드클리핑되지 않는다는 제약을 확인합니다. 작은동/큰동/경계가 복잡한동에서 화면에 선택범위가 들어오는지 봅니다.
6. 하단 브이월드 로고·출처가 가려지지 않는지 PC/모바일 실제환경에서 확인합니다.

## B. 자료층

공원은87위치/94OSM면으로 분리된 표기인지, 치평동11위치/16면 도형(포함된 스냅샷 기준)인지 확인합니다. 수치가 바뀌면 원자료 교체 여부와 기준일을 확인하세요.

무더위쉼터는 전체 페이지 수신/부분/실패를 구분합니다. 지도표시와 실제 개방이 일치하는지는 담당부서 확인이 필요합니다. 응급의료자료를 실시간 수용/빈병상으로 표시하지 않는지 점검합니다.

ITS영상은 실제 응답의 HTTPS/CORS/코덱을 확인하고, 닫은 뒤 영상 연결이 중지되는지 봅니다. 사고지역의2024표시와 실제소통정보의 시각을 구분합니다. 원본 CCTV URL에는 제공기관 토큰이 포함될 수 있으므로 공개 캡처하지 마세요.

AirKorea는 반환된 서구 측정소 위치·명칭·관측시각·점검플래그를 원문과 대조합니다. KMA는 nx/ny, 실황 기준시각, 예보 발표/유효시각을 대조합니다.

## C. 분석

침수WMS 네층을 하나씩 켜 보고 해당범위/빈도/출처를 확인합니다. 투명/공백 이미지를 안전으로 해석하지 않습니다. 시험지점의 원본 이미지를 공식원자료와 직접 대조합니다.

필지검색은PNU·필지경계·토지·건물 속성을 대조합니다. 현재연도 없는 값이나 권한제한을 다른자료로 대신하지 않습니다.

경사/단면은높이자료가 실제로연결된 경우에만 수행하고, 표본 누락을 유지합니다. 지형의기준면/해상도를확인합니다. GLB모형은공개 가능한시험파일로배치/회전/제거를시험합니다. 건물숨김미지원객체는지원불가로남깁니다.

## D. 실패 복원

자료 갱신에 실패했을 때 기존정상표시가남고 오류상태가보이는지 확인합니다. 구역 이동 중 이전요청의결과가뒤늦게현재동이름으로표시되지않는지 봅니다. 개인정보/비공개자료가없는지 최종확인합니다.

시험 증거에는 키나 개인 정보를 넣지 말고, 배포버전·브라우저·성능·수신일·자료기준일·확인항목·실패내용을 기록합니다.
