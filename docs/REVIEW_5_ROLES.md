# 5개 역할 관점의 통합 검토 기록

독립 에이전트 5명이 실제 병렬 실행되었다는 기록이 아니라, 한 구현 과정에서 역할별 검토 항목을 분리하고 결과를 교차 대조한 기록입니다. 가상의 회의 발언을 작성하지 않았습니다.

| 역할 | 발견한 문제 | 반영한 결정 |
|---|---|---|
| 행정경계·공간자료 | 기존 REST는 서구 외곽 1개, 권역 버튼은 카메라 이동뿐 | 18개 정확한 행정동명·실제 Polygon/MultiPolygon 검증, 내부 구멍·경계점 처리, 동별 필터 통일 |
| 3D·지도 | 브이월드 키를 넣어도 기본 OSM 시작. OSM 3D를 원본 모델과 혼동 | 설정 시 VWorld 선택, 가까이 보기, 높이·기울기 진단, SDK/타일/검증 상태 분리, 공식 facility_build 메서드만 사용 |
| 행정·안전·복지 자료 | 원자료 중복, 좌표 결측, 다른 서구, 2019년 쉼터, 민감한 거주시설 주소 | 325개 공개 자료 항목 정리, 대표위치의 한계 명시, 오래된 쉼터 제외, 공개 주소 32개 검수 대기, 인명·민감 주거시설 제외 |
| API·보안·갱신 | 단일 API 1페이지, 실패 시 갱신 상태 불분명 | 자료별 preset·매핑, 전체페이지 검사, 마지막 정상본 유지, 서버 키·허용 호스트·시간/크기 제한, 임의 URL 프록시 금지 |
| 사용성·검증 | 지도·표의 범위 불일치 가능, 단위와 0/결측 혼동 | 공통 상태의 동 필터, 원본 출처·기준일·처리일 분리, CSV/사업/통계 양식, 단위·날짜·좌표·오류 회귀시험 |

교차 검토에서 ‘API만 연결하면 모든 행정자료가 실시간이 된다’, ‘기둥 높이를 키우면 정확한 디지털트윈이다’, ‘서구라는 주소 문자열만 있으면 서구 시설이다’라는 구현을 채택하지 않았습니다. 공개본의 범위와 실제 인증이 필요한 연결을 구분했습니다.
