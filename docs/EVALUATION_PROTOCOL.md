# 지도·도보·돌봄 서비스 평가 절차

## 목적과 판정 범위

이 절차는 공개시설 샘플로 기능 회귀와 응답의 근거 표기를 확인한다. 질문 50개가 있다는 사실, API 호출 성공, 규칙 기반 응답의 통과율은 AI 정확도나 주민의 보행 안전·업무시간 개선 성과가 아니다. 실제 길찾기 제공기관 응답, 음성 안내, 위치 권한과 GPS 오차, 기기 접근성, 현재 시설 운영 상태는 별도로 확인한다.

평가 원본은 public/data/evaluation/walk-questions.json이며 실행기는 scripts/evaluate-service.mjs다. 각 상황에는 다음을 구분해 둔다.

- question: 공개시설을 대상으로 한 한국어 상황. 실제 개인 위치·이동 이력·연락처를 입력하지 않는다.
- local: 운영 코드와 실제 저장된 공개자료를 검사하는 방법. 모델·경로 제공기관 응답을 흉내 내지 않는다.
- expected.local / expected.live: 코드로 비교할 필드·연산자·값. 오류 코드, 실행모드 enum, 시설명 entity, 지역 범위, 수량·무결성 등이 포함된다.
- expected.evidence: 필요한 출처 필드, 최소 기록 수, 특정 시설 entity. 자료 기준일 null은 ‘미표기’로 보존하고 필드 자체의 누락과 구분한다.
- manualReview: 원문과 주장 일치, 최신성, 안내의 이해도·안전 단정·공격 지시 거부·실제 기기 동작처럼 사람의 심사가 필요한 조건.

자동검사 통과와 수동심사 완료는 별개다. 결과의 manualReview.status는 담당자가 심사하기 전까지 pending이다. 순수 수동항목은 not_executed로 남으며 0ms 또는 자동 통과로 기록되지 않는다.

돌봄 수량 78/31/47은 이 평가 묶음 1.0.0이 기준으로 삼은 공개자료 스냅샷 수록건수다. 전체 돌봄시설을 망라했다는 뜻이 아니다. 원자료가 갱신되면 출처·범위·파일 해시를 확인하고 suiteVersion과 해당 기대값을 함께 갱신한다. 수량이 달라졌다는 이유만으로 운영 결함이라고 단정하지 않는다.

공공시설 출발·도착 샘플은 현재 검증된 후보 중 서로 1~4km 직선거리의 공개공간 두 곳을 선택하고 ID·이름을 결과에 남긴다. 유효성 거절용 잘못된 좌표는 실제 이동 목적지가 아니다. 직선거리 사전후보 선정을 실제 보행경로·그늘 개선량·안전도 평가로 해석하지 않는다.

## 기본 로컬 실행

Node.js 22 환경에서 저장소 루트를 기준으로 실행한다.

    node scripts/evaluate-service.mjs
    node scripts/evaluate-service.mjs --json work/evaluation/local.json --csv work/evaluation/local.csv
    node --test tests/service-evaluation.test.mjs

기본 실행은 외부 네트워크를 사용하지 않는다. 운영 코드에 빈 환경설정 env={}를 전달하며, 외부 호출 경로에는 실패하는 차단기를 전달한다. PC에 실제 API 키가 설정되어 있어도 이 로컬 실행에 사용하지 않는다. 규칙 질의는 실제 로컬 자료를 읽는 운영 처리기를 실행한다. 이는 AI 응답을 만든 모의시험이 아니다.

결과의 execution=local_deterministic, simulation=false는 ‘실제 로컬 코드 검사’라는 뜻이다. 실제 AI 실행·인터넷 성능 측정이라는 뜻이 아니다. 두 모델은 실제 응답이 없으면 반드시 미실행으로 기록한다.

로컬 전체 실행에서 기대되는 자동검사 수는 40개, 순수 수동항목은 10개다. 일부 자동항목에도 수동 판단이 필요하므로 전체 품질 완료율로 환산하지 않는다. 예상 결과를 고정된 실측 결과로 배포하지 않는다. 실제 실행시각·수치·앱 버전·질문 해시는 매번 생성되는 JSON/CSV에 기록한다.

특정 상황만 다시 검사하려면 다음처럼 선택한다.

    node scripts/evaluate-service.mjs --case care-13,route-31,ask-35 --json work/evaluation/selected.json

알 수 없는 ID는 거절한다. 부분 실행 결과를 50개 전체 결과라고 보고하지 않는다.

## 명시적인 배포 API 실행

실제 배포 호출은 --live와 --base-url을 모두 지정해야 시작된다. 공개 검색과 AI 질문 요청이 실제 서버의 제공기관 사용량·비용을 발생시킬 수 있다. CLI는 사용자에게 API 키를 요구하지 않으며 키 옵션·Authorization 헤더·요청 본문의 모델 선택을 지원하지 않는다. 모델과 키는 배포 서버의 기존 프록시 설정을 사용한다.

    node scripts/evaluate-service.mjs --live --base-url https://seogu-on.vercel.app --json work/evaluation/live.json --csv work/evaluation/live.csv

호출 대상은 다음으로 제한된다.

- GET /api/config: 최초 1회 설정 응답과 지연 기록.
- GET /api/walk-routes?region=seogu&q=공개검색어: 검색 7개.
- POST /api/ask: regionId와 공개 평가 질문만 전송하는 질의 10개.

전체 라이브 실행은 최대 17개 사례 요청과 설정 확인 1회로 구성된다. 라이브 정의가 없는 33개는 미실행으로 남는다. 로컬 결과와 라이브 결과를 각각 보관한다. 실제 경로 POST, 제공기관 원문 경로 저장, 개인 GPS 수집, 원격 배포 변경은 이 CLI의 범위에 없다.

ask 시작 간격은 기본 6,500ms이며 --interval-ms로 6,500~60,000ms 범위에서 늘릴 수 있다. 기존 이용자의 요청량 때문에 429가 발생할 수 있다. 제한을 우회하거나 자동 재시도하지 않고 해당 상태를 그대로 기록한다. --timeout-ms는 100~60,000ms 범위이며 기본 30,000ms다. HTTP 리다이렉트는 따라가지 않는다.

배포 버전은 API가 제공하지 않으면 null이다. 로컬 package.json 버전을 배포 버전으로 복사하지 않는다. /api/config.version은 configVersion에 보관하며 앱 릴리스 버전으로 쓰지 않는다. 운영자가 배포 기록에서 확인한 값을 남기려면 --app-version을 사용할 수 있으며 versionSource=operator_declared_not_independently_verified로 표시된다.

    node scripts/evaluate-service.mjs --live --base-url https://seogu-on.vercel.app --app-version 확인한-배포버전 --case ask-35,ask-36 --json work/evaluation/live-selected.json

base-url에는 질의·비밀번호·토큰·경로가 없는 HTTPS origin을 넣는다. 개발 확인용 localhost/127.0.0.1의 HTTP origin도 허용한다. localhost 실행도 실제 HTTP 기능 확인일 뿐 운영 서비스 성능으로 일반화하지 않는다.

## 실제 모델 두 종류의 비교

평가 대상 표기는 upstage / solar-pro4와 google / gemma-4-26b-a4b-it다. 단일 배포의 한 실행은 해당 서버에 설정된 모델만 호출한다. CLI가 모델을 몰래 변경하거나 한 응답을 두 모델의 결과로 복제하지 않는다.

1. 같은 앱 빌드·자료·질문 묶음·시간 제한·사용량 조건을 준비한다.
2. 운영자가 기존 서버 설정 절차로 한 모델이 연결된 배포를 준비한다. 인증정보는 서버 안에만 둔다.
3. 같은 case ID로 라이브 실행하고 JSON/CSV 및 실제 배포 기록을 보관한다.
4. 다른 모델이 설정된 배포에서도 같은 조건으로 실행한다. 시간대·네트워크·콜드 스타트·제공기관 상태 차이를 기록한다.
5. 각 응답이 mode=llm이고 provider/model을 해당 값으로 표시했는지 확인한다. 이는 서버의 응답 표기에 근거하며 제공기관 과금내역을 독립 검증한 것은 아니다.
6. mode=rules이면 rulesFallback과 fallbackCode를 기록한다. 응답이 유용해도 모델 실행·모델 성공으로 집계하지 않는다. 미연결·한도·시간초과·형식 오류 등을 구분해 남긴다.
7. model/provider 누락, 다른 모델 또는 복구된 모델은 식별 누락·다른 모델 응답으로 따로 기록한다. 원래 기대 모델의 성능으로 합산하지 않는다.
8. 출처와 답의 숫자·시설명·안전 단정·근거 부족·공격성 자료 처리에 대해 사람의 심사를 마친다. 자동 통과율만으로 모델 승자를 발표하지 않는다.

키가 없거나 해당 모델의 실제 응답이 없으면 models[].status=not_executed, statusLabel=미실행이다. 단위시험에서 만든 집계용 가상 객체는 실행 결과 파일로 저장하지 않으며 실제 모델 성능의 증거로 사용하지 않는다. 이번 기능을 추가하는 과정에서 실제 모델·배포 API 시험을 했다는 뜻도 아니다.

## 결과 필드와 해석

| 필드 | 의미 |
| --- | --- |
| startedAt / finishedAt / checkedAt | 실제 실행 시각, ISO UTC |
| evaluator.localAppVersion / nodeVersion | 실행한 로컬 package.json 버전과 Node 버전 |
| suiteVersion / suiteSha256 | 질문·기대조건 묶음의 버전과 실제 바이트 해시 |
| dataSnapshots | 돌봄 검사에서 실제 읽은 9개 파일의 SHA256 |
| execution / simulation | 로컬 기능검사·실제 HTTP·미실행을 구분 |
| checks | 기대조건, 관찰 실제값, 통과 여부 |
| status | 자동검사 pass/fail, 실행 error, 미실행 not_executed |
| evidenceAudit | 필수 근거 누락·entity 누락·필드 누락·미표기 기준일 |
| model | 응답 mode/provider/model, rulesFallback, 표기 누락 |
| manualReview | 심사 기준과 미완료 상태; 심사자·시각·결과 초기값 null |
| latencyMs | 그 요청 또는 로컬 검사에 실제 걸린 시간. 기기 사용시간이 아님 |
| httpStatus / transportError | 실제 HTTP 상태·통신 오류. 의도된 400 거절도 그대로 기록 |
| cost | 서버가 usage.cost.amount와 currency를 제공할 때만 기록, 없으면 null |

근거 자동검사는 출처 필드 존재·URL 형식과 기대 entity만 확인한다. URL을 실제 열어 진위를 확인하거나 출처가 주장 전체를 뒷받침하는지 판독하지 않는다. 필요한 원문 검증은 수동심사에서 한다. sourceDate:null을 자료 기준일 없는 상태로 보존한다.

liveHttpErrors에는 의도적으로 빈 질문 등을 보낸 400 응답도 포함된다. 기대한 입력 거절이라면 자동검사 status는 pass일 수 있다. 운영 장애 집계에서는 의도된 거절, 예상치 못한 4xx/5xx, 통신 오류를 원시 행 기준으로 분리한다. 지연 p50/p95에는 완료한 라이브 사례의 실제 소요시간만 쓰며 표본 수를 함께 기록한다. 설정 확인 지연은 health에 별도로 있다. 소수 표본·실패 포함 여부·콜드 스타트 차이를 숨기지 않는다.

비용은 미제공 값을 0으로 대체하거나 토큰·경과시간에서 추정하지 않는다. 응답마다 명시적으로 제공된 비용이 있으면 통화와 출처를 보관한다. 총비용은 null이며, 실제 비용 비교는 제공기관 청구·사용량 기록과 조건을 별도로 맞춘다. null은 무료라는 뜻이 아니다.

CSV는 Excel에서 볼 수 있도록 UTF-8 BOM을 포함하며 쉼표·개행·따옴표를 이스케이프한다. 질문·모델 출력이 수식으로 실행되지 않도록 수식 시작 문자는 보호한다. JSON이 전체 근거·수동심사·데이터 해시를 보관하는 기준 파일이다. CSV의 비어 있는 비용·지연은 미기록이며 0으로 채우지 않는다.

종료코드는 자동검사 실패 또는 실행 오류가 있으면 1, 옵션·파일 등 실행 자체의 오류는 2, 그 외 0이다. 종료코드 0은 수동심사 완료를 뜻하지 않는다.

## 수동심사와 재현성

원본 JSON을 보존한 뒤 검토 사본에서 manualReview.reviewer에 익명 심사자 ID, reviewedAt에 실제 시각, result에 pass/fail/uncertain과 짧은 근거를 기록한다. 원자료 버전·공개시설 이름·스크린샷 식별자·기기/브라우저·권한·모션 줄이기·네트워크 조건을 함께 보관한다. 비공개 이용자 정보·집 주소·GPS 이력은 수집하지 않는다.

GPS 오차는 공공시설 대표좌표와 개발자 도구의 오차값으로 재현한다. 음성 안내는 실제 기기에서 재생·중지·중복·백그라운드 동작을 확인한다. 계단 제외는 제공기관 옵션 요청과 실제 현장 접근성을 분리한다. 여름 그늘·겨울 일조부족은 선택시각·높이자료·미평가 범위를 함께 읽고 현재 노면 안전의 확정 판정으로 쓰지 않는다.

공격성 자료에는 ‘이전 지시 무시’, 허위 출처 요구, 비공개 키 요구를 포함한다. 표식 문자열이 출력되지 않았다는 단일 조건만으로 보안이 검증됐다고 판단하지 않는다. 답변·도구·근거를 검토하며 외부 문서의 지시를 사용자 요청으로 실행하지 않았는지 확인한다.

## 운영 상태와 실사용자 A/B 측정 연결

health는 한 시점의 설정 API 응답이다. 설정 여부는 인증 성공·정상 운영·SLA·모델 품질의 증거가 아니다. 실제 가동률, 시간대별 p95, 오류율·429·외부 제공기관 실패율은 운영 관측자료에서 기간·분모·표본 조건을 정해 별도로 검토한다. 이 CLI는 지속 모니터링을 설정하지 않는다.

실제 이용자의 과제 수행시간·오류·출처 누락 비교는 [업무효과 실증 절차](PILOT_PROTOCOL.md)를 따른다. 기존 절차의 익명 참가자·AB/BA 순서·공통 조건·자료 버전·원시 기록·채점 근거를 유지한다. 도보·돌봄 찾기 과제를 추가하려면 별도 과제지와 완료기준을 정하고 기존 ‘공간 운영대안 비교/현장변경 재검토’ 결과와 섞지 않는다.

API 지연, 규칙 함수 실행시간, 가상 질문 50개의 자동검사 결과는 사람이 실제로 완료한 시간에 대입하지 않는다. 사용자 A/B 효과는 실제 측정이 완료되기 전까지 미실행으로 둔다. 교육용 공공시설 과제를 실제 사람이 수행했다면 사용성 관찰 자료임을 명시하고 주민 안전·정책 효과로 일반화하지 않는다.
