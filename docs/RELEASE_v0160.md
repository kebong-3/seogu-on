# 서구온 v0.16.0 — 도보 안내·현장조치·검증 준비

작성일: 2026-10-28. 운영 배포는 사이트의 버전과 최종 배포 검증 기록으로 확인한다. 아래에 로컬 자동검사와 실제 경로 제공기관 확인을 구분했으며 실제 단말·현장 보행은 별도로 검증해야 한다. 사용자 의견 36개 전체의 상태와 남은 조건은 [반영 상태표](FEEDBACK_36_STATUS.md)에 기록했다.

## 달라진 이용 흐름

지역을 고른 뒤 돌봄·생활안전, 계절 안심 도보 내비게이션, 재난안전지도의 세 가지 목적을 선택한다. 행정 검토가 필요한 사용자는 접힌 ‘행정 검토·자료 연결’에서 현장조치·대안 비교와 서비스·자료 상태를 연다. 이전 서비스의 표시·요청이 새 서비스 위에 남지 않도록 전환을 정리한다. 초기 공원 선택·동 선택 회전·지역 우선 메뉴는 앞선 변경을 유지한다.

### 도보 안내

제공기관에서 받은 보행 경로와 회전 지시를 바탕으로 현재 위치, 다음 안내, 남은 거리, 위치 오차를 표시한다. 사용자가 시작한 뒤 위치 권한을 요청하며 음성은 별도로 켠다. 지도 직접 조작은 위치 따라가기를 끄고 다시 켤 수 있다. 제공기관 지시가 없으면 출발·도착의 기본 안내를 제공하며 임의 회전을 만들어 넣지 않는다.

정확도가 낮거나 오래되거나 갑자기 이동한 위치는 진행·도착 판단에서 제외한다. 충분한 시간 동안 반복 확인한 경로 이탈에만 자동 재탐색을 요청하고 중복 요청과 짧은 간격의 반복 호출을 막는다. 정상적인 같은 도로 왕복을 역방향 이탈로 오인하던 경계조건을 회귀시험에 추가했다. 경로 선형이 끊긴 경우 안내를 보류한다.

종료·다른 서비스 선택·출도착 변경·경로 변경·결과 만료·패널 닫기·화면 숨김 시 위치 감시와 음성·진행 중 요청을 정리한다. 늦게 도착한 GPS·재탐색 응답이 안내를 재시작하지 않도록 한다. 실제 위치를 요청하지 않는 ‘안내 미리보기’도 제공한다. 미리보기는 GPS나 실제 보행 검증 결과가 아니다.

현재 출발 시각과 계절 예시 시각을 구분한다. 기존 계절 비교의 건물 그림자 근사·미평가 구간·자료 한계는 유지한다. 계단 제외 요청은 제공기관 옵션이며 휠체어·유모차 접근성 보증이 아니다.

주요 코드: [화면·위치 수명주기](../src/city/walking-navigation.js), [순수 길안내 모형](../shared/walk-navigation-model.js), [경로 UI](../src/city/walk-routes.js), [경로 서버](../server/walk-routes.js).

### 자연어 방문계획

‘장난감도서관에서 어린이도서관까지, 수유실 경유, 계단 제외’처럼 입력하면 실제 수록시설 ID에 연결한 출발·도착·경유·조건을 제안한다. 선택 결과와 근거를 확인하고 반영한 뒤 사용자가 도보경로를 조회한다. 모호한 시설을 임의로 확정하거나 경로 API를 자동 호출하지 않는다. 모델 응답도 수록 ID·필드·조건을 검증하며, 키가 없거나 모델이 실패하면 규칙 기반임을 표시한다. Google 모델이 더 이상 제공되지 않으면 같은 제공기관의 호환 모델을 한 번 찾아 전체 8초 안에서 재시도한다. 실제 응답 모델을 표시하며 Solar의 명시적 모델 선택은 바꾸지 않는다. 실제 Solar 성능 비교는 이번 로컬 검사에 포함되지 않는다.

### 현장조치와 운영 대안

실제 manifest와 공개자료의 시설 ID·명칭·주소·출처를 선택해 개인 검토과제를 만든다. 좌표 미확정 공식 시설은 주소 목록으로 선택할 수 있으며, 자유 입력은 위치 미검증으로 표시한다. 기존 과제의 대상 시설을 바꿔 다른 시설의 확인기록을 옮길 수 없다.

접수→검토→조치중→조치완료→현장확인의 순서로 진행한다. 단계 변경에는 담당 역할·확인일·근거가 필요하며, 완료 후 재개에는 사유가 필요하다. 수정과 재개 이력, 원자료 기준일과 확인 시각, 이용 가능/불가/미확인을 분리한다. 이름·연락처·민원인 정보를 입력하지 않도록 안내한다.

같은 지역의 개인 과제에 기록한 고유 시설 집합과 같은 일시를 사용해 A/B를 비교한다. 현재 확인기록과 임시 폐쇄·개방 가정을 구분하고 이용 가능·불가·미확인·가정 적용 수를 보여준다. UI는 대안별 한 시설의 가정, 모형은 복수 시설의 가정을 지원한다. 가정은 확인기록을 덮어쓰지 않는다. 이 수는 수요·안전도·실제 영업·정책 효과가 아니다.

저장은 지역별 **기기 내 개인 기록**이다. 다른 창의 수정과 같은 과제의 서로 다른 백업은 덮어쓰지 않고 거절한다. JSON 복원은 버전·지역·필드·이력·크기·중복을 검사하며 CSV는 수식 시작 문자를 보호한다. 가져온 시설이 현재 연결한 공개목록과 대조되지 않으면 이를 표시한다. 기관 공동 서버·계정·권한·승인·공식 감사 시스템은 구현하지 않았다.

주요 코드: [현장조치 화면](../src/city/field-operations.js), [모형](../shared/field-operations-model.js).

### 검색·상태·평가 준비

시설 검색은 문자의 정규화와 공백 처리, 명시적인 지역명 동치, 장난감대여소/장난감도서관·유아/어린이도서관·수유방/수유실의 별칭을 지원한다. 검색 방식과 제한을 알려주고 원 시설명·주소는 유지한다. 검색 결과와 선택한 시설에서 원자료 링크를 열 수 있고 기준일 미제공을 구분한다. 일반적인 오탈자 자동교정은 추가하지 않았다. 좌표 없는 목록을 경로 출도착점으로 임의 변환하지 않는다.

‘서비스·자료 상태’는 서버 설정 유무와 인증 성공을 구분하고, 자료 기준일·미제공·앱의 180일 재검토 기준을 보여준다. 경로 응답 성공·실패·평균시간은 **현재 서버 인스턴스 메모리의 임시 집계**다. 전체 계정의 가동률·사용량·SLA가 아니다. 운영비 화면은 사용자가 넣은 호출량·평균단가·고정비·검수시간으로 가정을 계산하며 빈칸은 미산정이다.

[50개 평가 상황](../public/data/evaluation/walk-questions.json)과 [실행기](../scripts/evaluate-service.mjs)를 추가했다. 기본 실행은 외부 호출 없이 실제 로컬 코드·공개자료를 검사한다. 자동 40개와 수동전용 10개를 구분하며 자동 항목에도 별도 수동심사 조건이 있다. 실제 배포 API 실행은 명시적인 `--live --base-url` 옵션이 필요하다. 이번 기록에서 Solar Pro 4·Gemma 실제 비교는 미실행, 미제공 비용은 null이다. 자세한 방법은 [평가 절차](EVALUATION_PROTOCOL.md)에 있다.

### 실증 기록과 자료 갱신

업무효과 측정에 완료/중단, 잘못된 선택, 확인 전화 횟수를 추가했다. 이전 기록의 빈 항목은 미측정으로 유지한다. 동일 과제의 양쪽 완료 기록이 있는 참가자 3명 이상일 때만 확인된 시간 개선을 계산한다. 완료율의 분모와 제외 수를 함께 표시하며, 실제 이용자 결과는 생성하지 않았다. 대표 도보 실증 절차는 [과제지](PILOT_WALKING_TASK.md)를 따른다.

공식 어린이집 자료를 별도 폴더에 수집해 추가·삭제·좌표 변경과 해시를 비교하는 검토 도구와 주간 작업을 추가했다. 실제 공식 원문 1,639행을 수동 수집해 서구 122건·순천 151건을 비교했다. 실제 현원 변경 서구 8건·순천 2건을 수집시각만 바뀐 기록과 분리했다. 검사 결과는 검토용 산출물이며 운영 자료를 자동 교체하지 않는다. 주간 CI 실행·담당 검토·전체 자료 갱신체계는 별도로 확인한다.

### 연결이 끊겼을 때

웹 앱 manifest와 연결 도움말을 추가했다. [service worker](../public/service-worker.js)는 `/offline.html`만 저장한다. API 응답·지도·GPS·경로를 오프라인 저장하지 않는다. 이미 열려 있는 화면의 유효한 경로는 메모리에 남을 수 있지만 새 경로 수신·재탐색은 연결이 필요하다. 화면 숨김 시 안내를 중지하므로 백그라운드 내비게이션을 제공하는 것으로 설명하지 않는다. 오프라인 지도 패키지나 설치형 전용 내비게이션이 아니다.

## 운영 API 확인에서 발견한 결함

초기 실제 API 평가 17개 중 14개가 통과했고 검색 3개가 원자료 링크 누락으로 실패했다. 공개 후보를 응답으로 바꾸는 단계가 sourceUrl·datasetId·sourceId를 누락한 것이 원인이어서 원문 링크와 ID를 보존하고 화면에도 연결했다. 로컬 평가도 실제 GET 처리기를 통과하도록 바꾸고 API·화면 회귀시험을 추가했다. 기대조건을 느슨하게 바꾸지 않았다. 수정 후 운영 재검사는 별도 배포 검증 기록으로 남긴다. 정상 질의 8개는 실제 Google gemini-3.8-flash 응답이었으며 Solar/Gemma 비교와 수동 품질심사는 미실행이다.

## 설치·설정과 인수 확인

Node.js 22 환경과 저장소 실행 방법은 [배포 안내](DEPLOY_VERCEL.md)를 따른다. [환경 예시](../.env.example)에 실제 비밀값을 넣어 커밋하지 않는다. 도보경로에는 서버의 TMAP 키가, Solar에는 `AI_PROVIDER=upstage`, `AI_MODEL=solar-pro4`, 서버의 `UPSTAGE_API_KEY`가 필요하다. [Solar 설정](SOLAR_SETUP.md)을 따른다. 키가 설정되었다는 사실만으로 인증 성공이나 실제 모델 응답을 확인한 것은 아니다. VWorld 브라우저 키는 제공기관의 도메인 제한을 확인한다.

자료의 출처·라이선스·수록 범위는 [돌봄 자료](CARE_DATA_SOURCES.md), [생활안전 자료](SAFETY_LIFE_SOURCES.md), [자료 한계](DATA_AND_LIMITS.md), 기존 SDK·지도 출처 문서를 유지한다. 실제 공개목록은 추가 78건 중 지도 31건/주소 47건이며, 이번 변경으로 47건의 좌표나 공식 귀갓길 선형을 새로 확보한 것은 아니다.

운영 인수 전에 확인할 것은 실제 단말 GPS·음성·권한, 정상/시간초과/거절/오프라인 복귀, 공식 출입구·운영조건·귀갓길·노면 자료, 두 모델의 동일과제 실행과 근거 심사, 실제 사용자 AB/BA 측정, 담당부서·검수주기·계약비용·장애대응이다. 기관 공동 저장·인증·승인이 필요하면 별도 서버 설계와 보안·보존 정책이 필요하다. 이 항목을 완료하지 않은 상태에서 업무효과·안전도·심사 점수를 확정하지 않는다.
