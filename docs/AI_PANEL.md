# 지도에게 묻기 (AI 질의 패널)

왼쪽 홈 패널의 **지도에게 묻기**를 누르면 열리는 질문 창입니다. "풍암동에서 그늘막이 150m 안에 없는 버스정류장은?"처럼 문장으로 물으면, 서구:온에 실린 공간자료만으로 짧게 답하고 결과 지점을 지도에 표시합니다.

- 답에 들어가는 숫자와 이름은 모두 공간 질의 도구(`server/spatial/tools.js`, MCP 서버와 같은 도구)의 결과에서 옵니다.
- 답 아래 **근거**에 조회한 내용, 출처와 기준일, 자료의 한계를 함께 보여 줍니다.
- 수록 자료는 모두 부분 자료입니다. 수록 건수는 서구 전체 시설 수가 아니고, 미연결 자료는 "0곳"이 아니라 "자료 없음"입니다.

## 두 가지 모드

| 모드 | 언제 | 동작 |
|---|---|---|
| AI 답변 (`mode: "llm"`) | `GEMINI_API_KEY`가 설정되어 있고 호출이 성공했을 때 | Google Gemini가 질문을 읽고 도구를 골라 부른 뒤, 도구 결과로 2~5문장의 답을 씁니다. |
| 규칙 기반 (`mode: "rules"`) | 키가 없거나, AI 호출이 실패했거나, 하루 한도를 넘었을 때 | AI 없이 정해진 규칙으로 동 이름·시설 종류·반경·"없는/가까운/비교/침수" 같은 표현을 찾아 도구를 부르고, 도구의 요약문으로 답합니다. |

키가 없어도 패널은 규칙 기반으로 동작합니다. 화면의 답 오른쪽 위에 **AI 답변** 또는 **규칙 기반** 표시가 붙습니다.

AI 모드에서도 서버가 한 번 더 확인합니다. AI가 쓴 답에 도구 결과에 없는 숫자(두 자리 이상)가 있으면 그 답을 버리고 규칙 기반 답으로 바꿉니다(`LLM_UNGROUNDED`).

## 설정 (환경변수)

| 변수 | 내용 | 기본값 |
|---|---|---|
| `GEMINI_API_KEY` | Google AI Studio에서 발급한 Gemini API 키. 서버 전용. | 없음(규칙 기반으로 동작) |
| `GEMINI_MODEL` | 사용할 모델 이름 | `gemini-2.5-flash` |
| `ASK_DAILY_LIMIT` | 하루(한국시간)에 AI를 호출할 최대 횟수. 넘으면 규칙 기반으로 답합니다. `0`이면 AI를 쓰지 않습니다. | `300` |

키 발급과 등록 순서(메뉴 이름은 시점에 따라 달라질 수 있어 일반적인 순서만 적습니다):

1. Google AI Studio(aistudio.google.com)에 Google 계정으로 들어가 API 키를 만듭니다.
2. Vercel 프로젝트 설정의 환경변수(Environment Variables) 항목에 `GEMINI_API_KEY`를 추가합니다. Production 환경에 넣습니다.
3. 환경변수만 바꾼 경우 자동으로 반영되지 않으므로 다시 배포(Redeploy)합니다.
4. 사이트에서 질문을 하나 해 보고 답에 **AI 답변** 표시가 붙는지 확인합니다. **규칙 기반**으로 나오면 아래 진단 코드를 봅니다.

로컬에서는 `.env.local`에 같은 이름으로 적고 `npm run dev`를 실행합니다.

모델 이름은 Google이 바꾸거나 종료할 수 있습니다. `LLM_MODEL_NOT_FOUND`가 나오면 Google AI Studio에서 현재 쓸 수 있는 모델 이름을 확인해 `GEMINI_MODEL`에 넣으세요.

## 진단 코드

AI 호출이 안 되면 응답의 `code`에 이유가 들어갑니다. 브라우저 개발자 도구의 네트워크 탭에서 `/api/ask` 응답을 보거나, 화면의 "규칙 기반" 표시에 마우스를 올리면 볼 수 있습니다. 이때도 답은 규칙 기반으로 나갑니다.

| code | 뜻 | 조치 |
|---|---|---|
| `LLM_NOT_CONFIGURED` | `GEMINI_API_KEY`가 없음 | 키를 등록하고 다시 배포 |
| `LLM_KEY_REJECTED` | 키가 거부됨(오타, 만료, 키 제한 설정) | 키를 다시 복사하거나 새로 발급 |
| `LLM_MODEL_NOT_FOUND` | 모델 이름을 찾지 못함 | `GEMINI_MODEL`을 현재 제공되는 이름으로 변경 |
| `LLM_QUOTA` | Google 쪽 사용량 한도 초과(HTTP 429) | 잠시 뒤 다시 시도, 요금제·한도 확인 |
| `LLM_TIMEOUT` | 시간 안에 응답이 오지 않음 | 일시적이면 그대로 둠. 반복되면 더 빠른 모델로 변경 |
| `LLM_BAD_REQUEST` | Google이 요청 형식을 거부함(HTTP 400) | 모델이 도구 정의 형식을 받지 않는 경우. 모델을 바꾸거나 `server/ai/gemini.js`의 변환을 수정 |
| `LLM_BAD_RESPONSE` | 응답이 비었거나 차단됨, 형식 오류, 서버 오류(5xx), 정해진 횟수 안에 답을 끝내지 못함 | 일시적이면 그대로 둠. 반복되면 모델 변경 |
| `LLM_UNGROUNDED` | AI 답에 도구 결과에 없는 숫자가 있어 버림 | 조치 불필요(안전장치가 동작한 것) |
| `LLM_DAILY_LIMIT` | 하루 AI 호출 한도(`ASK_DAILY_LIMIT`) 도달 | 다음 날 풀림. 필요하면 한도 조정 |

요청 자체가 거절되는 경우(답이 나가지 않음): `METHOD_NOT_ALLOWED`(405, POST만 받음), `CROSS_ORIGIN`(403, 다른 사이트에서 온 요청), `RATE_LIMITED`(429, 같은 IP에서 1분에 10회 초과), `BODY_TOO_LARGE`(413, 8KB 초과), `BAD_JSON`·`BAD_REQUEST`·`QUESTION_REQUIRED`·`QUESTION_TOO_LONG`(400, 질문은 300자 이하).

## 비용 관리

AI 호출 비용은 키를 발급한 계정에 청구됩니다.

- 질문 하나에 모델 호출은 최대 4번, 도구 실행은 최대 6번, 전체 시간은 약 11초로 제한합니다.
- 같은 IP에서 1분에 10번까지만 받습니다. 이 제한과 하루 한도는 서버 인스턴스 메모리에서 세는 임시 제한입니다. 인스턴스가 여러 개 뜨거나 다시 시작되면 따로 세므로, 실제 호출 수는 `ASK_DAILY_LIMIT`보다 많아질 수 있습니다.
- 확실한 상한이 필요하면 Google 쪽(프로젝트 한도, 결제 예산 알림)에서도 한도를 걸어 두세요.
- AI를 잠시 끄려면 `ASK_DAILY_LIMIT=0`으로 두거나 `GEMINI_API_KEY`를 지우고 다시 배포합니다. 패널은 규칙 기반으로 계속 동작합니다.

## 개인정보와 기록

- 질문 문장은 **AI 모드일 때만** Google의 Gemini API로 전송됩니다. 규칙 기반 모드에서는 외부로 나가지 않습니다.
- 함께 보내는 것은 질문, 화면에서 고른 동 이름, 이번 방문에서 한 직전 질문 최대 3개, 그리고 도구 결과(공개 자료)입니다. 좌표와 내부 식별자는 모델에게 보내지 않습니다.
- 사이트 서버는 질문 내용을 로그에 남기거나 저장하지 않습니다. 실패했을 때 진단 코드만 로그에 남깁니다.
- Google이 전송된 내용을 어떻게 다루는지는 사용하는 요금제와 Google의 약관에 따릅니다. 질문 창에 이름·주소·전화번호 같은 개인정보를 적지 않도록 안내하세요.

## 아직 확인하지 못한 것

`server/ai/gemini.js`의 Gemini 요청·응답 형식은 문서 기억에 따라 작성했고, 개발 환경에서 Google 서버에 연결할 수 없어 실제 호출로 검증하지 못했습니다(`tests/ask-llm.test.mjs`는 가짜 응답으로 시험합니다). 키를 등록한 뒤 첫 질문에서 **AI 답변** 표시가 나오는지 꼭 확인하세요. 형식이 맞지 않으면 답은 규칙 기반으로 나가고 `code`에 이유가 남습니다.
