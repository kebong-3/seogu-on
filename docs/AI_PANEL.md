# 지도에게 묻기 (AI 질의 패널)

상단 날씨 표시줄 오른쪽의 **지도에게 묻기**에 언제든 질문할 수 있습니다. 좁은 화면에서는 날씨 아래에 전체 너비 입력창이 표시됩니다. 왼쪽 홈 카드에서도 같은 결과 패널을 열 수 있습니다. "치평동 폭염 대응 점검자료 정리해줘" 또는 "풍암동에서 그늘막이 150m 안에 없는 버스정류장은?"처럼 물으면 공개 공간자료를 조회·계산하고, 필요한 계절 대응 질문에서는 기상청 관측을 함께 확인합니다.

- 공간 수치·위치·업무별 확인사항은 공간 질의 도구(`server/spatial/tools.js`, MCP 서버와 같은 도구)가 계산합니다. AI에는 이 근거와, 업무 질문에서 실제 수신한 기상청 관측을 전달합니다. 생성 설명은 담당자가 근거와 대조해야 합니다.
- 답 아래 **근거**에 조회한 내용, 출처와 기준일, 자료의 한계를 함께 보여 줍니다.
- 수록 자료는 모두 부분 자료입니다. 수록 건수는 서구 전체 시설 수가 아니고, 미연결 자료는 "0곳"이 아니라 "자료 없음"입니다.
- 출처에 유효한 HTTP(S) 주소가 있으면 원문을 열 수 있습니다. **검토메모 복사·저장**에는 질문, 당시 선택 구역, 응답 방식, 결과 지점, 출처·기준일·관측시각, 담당자 확인사항과 자료 한계가 함께 담깁니다.
- 지도 연결 전에도 결과 목록과 근거를 볼 수 있습니다. 지도에 넘긴 대상 수와 실제 지도 엔진의 렌더 성공을 같은 것으로 표현하지 않습니다. 질문 후 다른 동을 선택하면, 이전 응답은 사용자의 지도를 자동으로 바꾸지 않습니다.

## 대표 사용 흐름

1. "치평동 폭염 대응 점검자료 정리해줘": 무더위쉼터·그늘막·쿨링포그 조회, 정류장과 그늘막 공백 후보 계산, 기상청 대표위치 관측, 현장 확인사항을 확인합니다.
2. "결빙 관리지점 점검자료 정리해줘": 현재 선택 구역의 상습결빙 관리지점과 제설 관련 수록자료를 찾고 기상 관측을 덧붙입니다. 미확보 자료는 별도로 표시하며 현재 결빙을 판정하지 않습니다.
3. "침수 이력 현장점검 준비해줘": 과거 피해 기록·대피 관련 자료와 강수 관측을 구분해 확인하고 검토메모를 가져갑니다. 과거 피해 건수는 현재 위험도나 향후 침수 예측이 아닙니다.

업무 묶음은 폭염·한파·결빙·침수·통학환경·생활시설 6종입니다. `work_brief`는 여러 자료를 실제 조회하고 `brief.evidence`, `nextActions`, `missingData`를 반환합니다. 확인사항은 공개자료의 한계에 맞춘 업무 검토 항목이며 AI가 새로운 법적 기준이나 최적 입지를 확정하는 기능이 아닙니다. 기본 비교 반경(폭염 150m·한파 300m)은 검토 가정이며 법정 설치기준이 아닙니다.

계절 대응 4종은 서버의 `readWeather`로 기상청 초단기실황을 추가 조회합니다. 5초 안에 받지 못하면 `weather_observation` 실패를 보존하고 기존 공간근거는 유지합니다. 복수 동 질문에서는 첫 업무구역의 대표위치 관측만 사용하며 그 범위를 명시합니다. 모델에 질문 문장을 기상청으로 보내지는 않습니다.

## 두 가지 모드

| 모드 | 언제 | 동작 |
|---|---|---|
| AI 답변 (`mode: "llm"`) | 공급자 연결 설정이 유효하고 호출이 성공했을 때 | 명확한 공간·업무 질문은 서버가 근거를 준비하고 AI가 1회 호출로 설명합니다(`analysisPath: grounded-summary`). 그 밖의 질문은 AI가 도구를 선택·호출합니다(`tool-selection`). 실제 수행한 역할을 결과에 구분합니다. |
| 규칙 기반 (`mode: "rules"`) | 키가 없거나, AI 호출이 실패했거나, 하루 한도를 넘었을 때 | AI 없이 정해진 규칙으로 동 이름·시설 종류·반경·"없는/가까운/비교/침수" 같은 표현을 찾아 도구를 부르고, 도구의 요약문으로 답합니다. |

키가 없어도 패널은 규칙 기반으로 동작합니다. 화면의 답 오른쪽 위에 **AI 답변** 또는 **규칙 기반** 표시가 붙습니다.

AI 모드에서도 서버가 한 번 더 확인합니다. AI가 쓴 답에 도구 결과에 없는 숫자(두 자리 이상)가 있으면 그 답을 버리고 규칙 기반 답으로 바꿉니다(`LLM_UNGROUNDED`).

이 검사는 일부 숫자의 일치 여부 검사이며 고유명사·인과관계 등 답변 전체의 사실성을 보장하지 않습니다. 원문 근거와 현장 상태를 확인해야 합니다. Gemma 4에는 공식 지원되는 `thinkingLevel: minimal`을 사용해 짧은 근거 요약의 지연을 줄입니다. 데이터 조회·거리 계산·출처 확인 단계는 생략하지 않습니다.

## 설정 (환경변수)

| 변수 | 내용 | 기본값 |
|---|---|---|
| `GEMINI_API_KEY` | Google AI Studio에서 발급한 Gemini API 키. 서버 전용. | 없음(규칙 기반으로 동작) |
| `AI_PROVIDER` | `google` 또는 `openai-compatible` | `google` |
| `AI_MODEL` | 사용할 모델 이름(모델 교체용) | `gemma-4-26b-a4b-it` |
| `GEMMA_MODEL`, `GEMINI_MODEL` | 기존 모델 설정과의 호환. 우선순위는 `AI_MODEL` → `GEMMA_MODEL` → `GEMINI_MODEL` → 기본값이며 명시한 모델 계열을 임의로 변경하지 않습니다. | 없음 |
| `AI_API_KEY` | 공급자 서버 전용 키. Google에서는 기존 `GEMINI_API_KEY`도 사용 가능 | 없음 |
| `AI_API_BASE` | 호환 서버의 `/v1` 기본주소. 서버 환경변수로만 설정 | 없음 |
| `ASK_DAILY_LIMIT` | 하루(한국시간)에 AI를 호출할 최대 횟수. 넘으면 규칙 기반으로 답합니다. `0`이면 AI를 쓰지 않습니다. | `300` |

키 발급과 등록 순서(메뉴 이름은 시점에 따라 달라질 수 있어 일반적인 순서만 적습니다):

1. Google AI Studio(aistudio.google.com)에 Google 계정으로 들어가 API 키를 만듭니다.
2. Vercel 프로젝트 설정의 환경변수(Environment Variables) 항목에 `GEMINI_API_KEY`를 추가합니다. Production 환경에 넣습니다.
3. 환경변수만 바꾼 경우 자동으로 반영되지 않으므로 다시 배포(Redeploy)합니다.
4. 사이트에서 질문을 하나 해 보고 답에 **AI 답변** 표시가 붙는지 확인합니다. **규칙 기반**으로 나오면 아래 진단 코드를 봅니다.

로컬에서는 `.env.local`에 같은 이름으로 적고 `npm run dev`를 실행합니다.

모델 이름은 Google이 바꾸거나 종료할 수 있습니다. 첫 요청이 404일 때 서버는 같은 키로 Models API를 조회해 `generateContent`를 지원하는 같은 Gemma 4 계열의 안정형 모델을 한 번 시도합니다. 다른 모델 계열·미리보기·이미지 모델은 자동 선택하지 않습니다. 전체 25초 예산 안에서만 복구하며 키 거부·한도 오류는 재시도하지 않습니다. 성공하면 실제 모델과 `modelRecovered`를 응답과 화면에 표시합니다. 복구까지 실패하면 규칙 기반임을 명시합니다. 계속 `LLM_MODEL_NOT_FOUND`가 나오면 현재 제공되는 모델 및 프로젝트의 접근 권한을 확인해 `AI_MODEL`을 변경하세요.

## 진단 코드

AI 호출이 안 되면 응답의 `code`에 이유가 들어갑니다. 화면에는 시간초과·미연결 등을 쉬운 문장으로 안내하고 **응답 상태 자세히**에서 코드를 볼 수 있습니다. 브라우저 개발자 도구의 네트워크 탭에서도 `/api/ask` 응답을 확인할 수 있습니다. 이때도 확보된 근거는 규칙 기반 결과로 제공합니다.

| code | 뜻 | 조치 |
|---|---|---|
| `LLM_NOT_CONFIGURED` | `GEMINI_API_KEY`가 없음 | 키를 등록하고 다시 배포 |
| `LLM_KEY_REJECTED` | 키가 거부됨(오타, 만료, 키 제한 설정) | 키를 다시 복사하거나 새로 발급 |
| `LLM_MODEL_NOT_FOUND` | 모델 이름을 찾지 못함 | `AI_MODEL`을 현재 제공되는 이름으로 변경 |
| `LLM_QUOTA` | 연결된 AI 제공기관의 사용량 한도 초과(HTTP 429) | 잠시 뒤 다시 시도, 제공기관 한도 확인 |
| `LLM_TIMEOUT` | 시간 안에 응답이 오지 않음 | 일시적이면 그대로 둠. 반복되면 더 빠른 모델로 변경 |
| `LLM_BAD_REQUEST` | 연결된 AI 제공기관이 요청 형식을 거부함(HTTP 400) | 설정한 모델과 요청 규격 확인 |
| `LLM_BAD_RESPONSE` | 응답이 비었거나 차단됨, 형식 오류, 서버 오류(5xx), 정해진 횟수 안에 답을 끝내지 못함 | 일시적이면 그대로 둠. 반복되면 모델 변경 |
| `LLM_UNGROUNDED` | AI 답에 도구 결과에 없는 숫자가 있어 버림 | 조치 불필요(안전장치가 동작한 것) |
| `LLM_DAILY_LIMIT` | 하루 AI 호출 한도(`ASK_DAILY_LIMIT`) 도달 | 다음 날 풀림. 필요하면 한도 조정 |

요청 자체가 거절되는 경우(답이 나가지 않음): `METHOD_NOT_ALLOWED`(405, POST만 받음), `CROSS_ORIGIN`(403, 다른 사이트에서 온 요청), `RATE_LIMITED`(429, 같은 IP에서 1분에 10회 초과), `BODY_TOO_LARGE`(413, 8KB 초과), `BAD_JSON`·`BAD_REQUEST`·`QUESTION_REQUIRED`·`QUESTION_TOO_LONG`(400, 질문은 300자 이하).

## 비용 관리

AI 호출 비용은 키를 발급한 계정에 청구됩니다.

- 근거를 먼저 계산하는 경로는 정상 응답 시 모델 1회 호출로 끝납니다. 자유질문 도구선택 경로는 모델 대화 최대 4회·도구 실행 최대 6회입니다. 전체 25초 예산에 기상 조회에 쓴 시간도 포함합니다. 첫 모델이 404이면 목록 조회 1회와 대체 모델 요청 1회가 추가될 수 있습니다.
- 같은 IP에서 1분에 10번까지만 받습니다. 이 제한과 하루 한도는 서버 인스턴스 메모리에서 세는 임시 제한입니다. 인스턴스가 여러 개 뜨거나 다시 시작되면 따로 세므로, 실제 호출 수는 `ASK_DAILY_LIMIT`보다 많아질 수 있습니다.
- 확실한 상한이 필요하면 Google 쪽(프로젝트 한도, 결제 예산 알림)에서도 한도를 걸어 두세요.
- AI를 잠시 끄려면 `ASK_DAILY_LIMIT=0`으로 두거나 `GEMINI_API_KEY`를 지우고 다시 배포합니다. 패널은 규칙 기반으로 계속 동작합니다.

## 개인정보와 기록

- AI 연결이 설정되고 호출 한도가 남아 있으면 질문 문장은 설정한 모델 서버로 전송됩니다. 기본은 Google API의 Gemma이며 호환 서버를 설정하면 해당 서버로 전송됩니다. 호출 실패 후 결과가 규칙 기반으로 표시되어도 이미 전송을 시도했을 수 있습니다. AI 미설정·비활성화·호출 한도 도달 시 모델 서버에 질문을 보내지 않습니다.
- 함께 보내는 것은 질문, 화면에서 고른 동 이름, 이번 방문에서 한 직전 질문 최대 3개, 그리고 도구 결과(공개 자료)입니다. 도구 결과를 줄일 때 좌표와 내부 식별자는 제외합니다. 사용자가 질문 자체에 적은 내용은 질문의 일부로 전송됩니다.
- 사이트 서버는 질문 내용을 로그에 남기거나 저장하지 않습니다. 실패했을 때 진단 코드만 로그에 남깁니다.
- Google이 전송된 내용을 어떻게 다루는지는 사용하는 요금제와 Google의 약관에 따릅니다. 질문 창에 이름·주소·전화번호 같은 개인정보를 적지 않도록 안내하세요.

## 아직 확인하지 못한 것

모의 응답 시험과 실제 운영 호출 검증을 구분합니다. 모델을 교체한 후 응답의 `mode`, `model`, `analysisPath`, 도구 호출 근거를 확인해야 합니다. 명시한 기존 `GEMINI_MODEL`도 설정 우선순위에 따라 존중합니다. 두 공급자 형식의 모의 시험 성공은 실제 모델 2종 운영 성공의 증거가 아닙니다.

## 자체 모델 서버 연결

Gemma, Llama 등 도구 호출을 지원하는 모델을 vLLM 등의 Chat Completions 호환 서버에 올린 후 `AI_PROVIDER=openai-compatible`, `AI_MODEL=서버의 모델 식별자`, `AI_API_BASE=https://기관서버/v1`, `AI_API_KEY=서버키`로 설정합니다. 모델별 도구 호출 파서와 템플릿은 서버 운영자가 활성화해야 합니다. 이 연결 규격이 정부 공통기반의 실제 접속주소·인증규격을 확인했다는 뜻은 아닙니다. 해당 규격이 제공되면 어댑터를 대조해야 합니다.

로컬 검증에서는 `http://127.0.0.1:8000/v1`을 사용할 수 있습니다. Vercel 배포에서 로컬 주소는 허용하지 않습니다. 키·연결주소를 브라우저 입력이나 URL로 받지 않으며 리다이렉트를 따르지 않습니다. 공간 도구, 호출 한도, 근거 검사와 보고서 계산은 모델 공급자와 분리됩니다.
