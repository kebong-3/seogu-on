# 순천 실제 지역 자료팩

수집일: **2026-10-23**. 적용 지역: **전남광주통합특별시 순천시**.

순천을 서구온의 두 번째 실제 지역으로 조회하고 같은 공공공간 검토·운영 대안 비교 흐름을 사용할 수 있도록 공개 경계와 개방공간 자료를 정규화했다. 지역명과 지도 중심만 바꾼 예시가 아니다. 지역 프로필, 24개 읍면동 경계, 원문 좌표가 있는 67개 공간, 출처·기준일·검사 결과가 각각 연결된다.

이 자료팩은 **공개자료의 실제 지역 적용**을 입증한다. 순천시 담당자가 사용해 성과를 검증했다는 의미의 업무 실증이나 순천 전체 공공시설 전수조사를 의미하지 않는다.

## 3. 동일 공간과 복수 조건 처리

공개 표준데이터에는 영구적인 방·공간 ID가 없다. 따라서 **제공기관코드 + 공백을 정리한 공간명 + 광역 행정명을 제외한 정규화 주소**로 같은 공간을 묶었다. 같은 건물 안에서도 회의실 이름이 다르면 별도 공간으로 유지한다. 날짜, 운영시간, 요금, 정렬 순서는 ID 생성에 사용하지 않는다.

동일 공간명의 여러 행은 최신 행 하나로 무조건 덮어쓰지 않았다. 예를 들어 순천만국가정원 습지센터 소회의실 5(1층)는 같은 좌표·공간명으로 운영시간과 사용료가 다른 2행이 제공된다. 공간 수는 1개로 세고, 두 원문 행과 조건을 모두 보존한다. `00:00~23:59` 또는 `00:00~00:00` 원문을 24시간 개방이나 휴관 확정으로 해석하지 않는다.

- `sourceRecordCount`: 해당 공간에 연결된 원문 행 수.
- `sourceRecordHashes`: 보존한 78행 원문과 대조하는 해시.
- `sourceConditionVariants`: 원문 운영시간·유료 여부·사용 기준시간·요금 조건.
- `publishedFacilityType`, `publishedCapacity`, `publishedArea`: 원문 유형·수용인원·면적 참고치.
- `hours`: 원문 시간. 조건이 여러 개이면 담당자 확인 필요를 함께 표시한다.
- `reviewStatus: unverified`: 공개자료 수록 상태. 현장확인 완료를 의미하지 않는다.

내부 ID는 `identity-registry.json`에 보관한다. 원자료에 영구 공간 ID가 없으므로 공간명·주소가 바뀌면 동일 공간인지 담당자가 대조한 뒤 새 `sourceKey`를 기존 ID에 연결해야 한다. 자동 병합으로 기존 확인기록이 다른 공간에 붙는 일을 피한다. 수집 결과의 `identityChanges`는 새 ID와 이번 수신에서 사라진 ID를 별도로 알려준다. 수신에서 사라졌다고 폐쇄로 처리하지 않는다.

## 4. 파일과 갱신 방법

| 파일 | 역할 |
| --- | --- |
| `public/data/regions/suncheon.json` | 표시 이름, 코드 체계, 범위, 실제 자료 URL, 지원 기능 |
| `public/data/regions/suncheon/admin-boundaries.geojson` | 24개 읍면동 원본 도형과 라벨점 |
| `public/data/regions/suncheon/facilities.geojson` | 검토에 사용하는 고유 공간 67개 |
| `public/data/regions/suncheon/public-facilities-source.json` | 병합 전 순천 원문 78행 |
| `public/data/regions/suncheon/identity-registry.json` | 날짜·시간·요금에 독립적인 내부 공간 ID 연결표 |
| `public/data/regions/suncheon/validation.json` | 구조·범위 검사 결과, 수록 범위, 원본 해시, ID 변화 |
| `scripts/data/collect-suncheon.mjs` | 공개 다운로드 수집·추출·병합·검증·저장 |
| `tests/suncheon-data.test.mjs` | 실제 자료팩 회귀 검사 |

새 공개 다운로드를 받을 때:

```sh
node scripts/data/collect-suncheon.mjs --fetch /tmp/suncheon-public-download
node scripts/validate-region.mjs --profile suncheon
node --test tests/suncheon-data.test.mjs
```

이 명령은 저장소 안 순천 자료팩을 갱신하므로 결과를 검토한 뒤 커밋한다. 네트워크 접근은 공개 경계·공공데이터포털에만 필요하다. 자료 양식·행정구역 수·이용조건이 달라지면 수집기가 실패하게 하여 사람이 변화를 검토하도록 했다. 현재 경계 원본 버전은 2026-07-01로 고정했으므로 이후 경계 버전을 채택할 때 URL·기준일·예상 행정구역 수와 회귀 기준을 함께 검토한다.

저장해 둔 원본을 다시 변환할 때는 `--source-dir /원본폴더`를 사용한다. 폴더에는 `national-boundaries.geojson`, `national-facilities.json`, `facility-columns.json`, `facility-suncheon-detail.html`, **실제 수집시각을 기록한 `download.json`**이 있어야 한다. 재변환 시점을 원자료 수집시각으로 바꾸지 않는다. 같은 원본으로 재실행하여 67개 ID가 유지됨을 확인했다.

## 5. 검증과 행정 활용의 범위

공통 `validateRegionDataPack`과 배포 프로필 로더 검사에서 **24개 경계·67개 공간, 경고 0개**를 확인했다. 별도로 24개 도형이 전국 원본과 완전히 동일하고, 각 공간에 연결된 78개 원문 행의 명칭·좌표가 그대로 보존되었는지 대조했다. 모든 지도 라벨점은 해당 읍면동 내부이고 모든 공간점은 지정된 읍면동 내부다.

실제 67개 공간을 공통 비교 엔진에 넣은 회귀 검사에서 초기 현장확인 기록은 0건이며, 토요일 14~17시의 현재 확인상태는 **미확인 67개**다. 공개 운영시간이 있더라도 실제 개방·예약 가능으로 승격하지 않는다. 담당자가 확인기록을 입력하고, 별도의 변경안을 가정으로 설정해야 비교 근거가 생긴다.

예를 들어 다음 실제 공간을 지방행정 검토 후보로 사용할 수 있다.

- **마을의제·주민회의:** 장천파랑새창고 교육회의실, 국가정원 회의실 등의 자료와 원문 운영조건을 조회하고 담당자 확인 후 저녁·주말 운영안을 비교한다.
- **생활문화·청년 활동:** 생활문화센터 영동1번지의 동아리실·음악실·녹음실을 목적별 후보로 찾고 공간별 이용 조건과 관리 인력을 검토한다.
- **돌봄·부모교육:** 육아종합지원센터 강당 등을 검토 후보로 연결한다. 수용인원·접근성·행사 일정은 추가 확인한다.
- **생활체육:** 상사종합체육관, 팔마체육시설 등 수록 공간의 시간대별 운영안과 추가 운영비 가정을 비교한다.

수록되지 않은 읍면동의 공백을 곧바로 생활SOC 부족, 주민 수요, 취약성 또는 정책 우선순위로 바꾸지 않는다. 인구·이용량·수요·실제 보행경로·운영 실적 등을 추가 확인해야 그러한 판단을 뒷받침할 수 있다. 기존 서구 전용 재난·교통·기상 호출은 순천에서 `legacySeoguServices: false`로 유지하며, 순천 자료로 검증하지 않은 API가 연결된 것처럼 표시하지 않는다.
