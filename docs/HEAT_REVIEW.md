# 폭염 대응 대안 검토

홈의 **폭염 대응계획**에서 구역과 거리 조건을 지정하고 **두 안 비교하기**를 누릅니다. A는 기존 쉼터와의 연결, B는 A에 추가 설치 후보를 더한 검토안입니다. 기존 3D 그림자 기능은 패널 아래에서 열 수 있습니다.

## 계산과 입력

- 버스정류장 OSM 부분 공개본, 서구 그늘막, 국민안전24 공식 무더위쉼터 공개본을 이용합니다. 보조 API 쉼터를 중복 합산하지 않습니다.
- 선택 구역의 정류장 중 설정 거리 안에 그늘막 대표점이 없는 지점을 검토합니다. 실제 그늘 유무나 행정 미비를 판정하지 않습니다.
- 동 경계 밖 인접시설도 놓치지 않도록 시설 검색은 서구 공개본 전체를 대상으로 합니다.
- 기존 쉼터 연결조건 이내인 지점을 먼저 제안합니다. 나머지 자동 설치 후보는 최근접 그늘막 거리 내림차순으로 제안하며, 담당자가 명시적으로 고른 설치 후보를 먼저 반영합니다. 상한과 입력한 첫해 예산을 넘는 후보는 추가 검토 상태입니다. 이 순서는 위험도나 최적 입지 순위가 아닙니다.
- 비용 단위는 만원입니다. 기존안 전체의 연간 추가 운영비, 신규 1지점 설치비, 신규 1지점 연간 유지비, 기간, 첫해 한도를 입력할 수 있습니다. 빈칸은 미산정이며 0원은 직접 입력해야 합니다.
- B 첫해 = 기존 연간 운영비 + 신규 수 × (설치비 + 유지비). B 기간비용 = 기존 연간 운영비 × 기간 + 신규 수 × (설치비 + 유지비 × 기간). 동일 가격, 물가·할인율 미적용입니다.
- 신규 수가 0이면 신규 단가가 없어도 기존안 비용으로 계산합니다. 기존 운영비·신규 단가·유지비 중 필요한 값이 없으면 예산 내 가능 여부를 판정하지 않습니다.

## 담당자 기록과 보고서

후보를 펼치면 대응방안, 미검토/현장 확인 기록/보류, 확인내용을 작성할 수 있습니다. 현장 확인 상태에는 내용이 필요합니다. 위치 보기와 연결 쉼터 보기로 지도에서 확인합니다. 검토조건이 달라지면 이전 보고서의 출력이 막히며 다시 비교해야 합니다.

선호안과 선정 근거를 작성한 뒤 보고서를 미리보고 HTML로 내려받거나 인쇄 창에서 PDF로 저장합니다. JSON에는 계산 결과, 조건, 후보별 기록, 자료 SHA-256이 포함됩니다. 입력은 현재 브라우저의 localStorage에만 보관됩니다. 다른 기기로의 복원 및 조직 공동 저장은 이번 범위에 포함하지 않습니다. 원자료는 읽기 전용입니다. 자료 해시가 바뀌면 과거 확인상태를 초기화합니다.

보고서 숫자는 순수 계산 결과를 재사용합니다. 생성형 AI가 수치·성과·안전 판정을 만들지 않습니다. 보호 인원, 온도 저감, 실제 운영 가능성은 계산하지 않습니다. 신규 위치는 정류장 대표점이며 보도 폭, 지장물, 점용·관리 협의와 실제 그늘 검증이 필요합니다.

## 수용 시험

1. 풍암동 / 그늘막 150m / 쉼터 300m / 신규 상한 3 → 수록 정류장 37, 그늘막 근접 14, 검토 대상 23, 기존 연결 17지점·7쉼터, 추가 설치 3지점, 나머지 3지점.
2. 비용을 모두 비워두면 두 안 모두 미산정.
3. **시험 가정** 운영 100, 설치 200, 유지 10, 기간 3년, 첫해 730 → A 첫해 100·3년 300, B 첫해 730·3년 990만원. 실제 견적이 아닙니다.
4. 후보 보류 시 수치와 보고서가 함께 변경. 조건 변경 시 보고서 비활성화. 확인내용 없이 현장 확인 상태를 설정하지 못함.
5. 모델 404 → 모델 목록 확인 → 안정형 Flash 1회 재시도; 계속 실패하면 원인코드를 보존한 규칙 기반 답변.

자동 검증: `node --test tests/heat-plan.test.mjs tests/ask-model-recovery.test.mjs`. 전체 검증: `npm run verify`. 실제 AI 성공 여부는 배포 환경에서 응답의 `mode: llm`, 모델명, 도구 근거를 함께 확인해야 합니다.
