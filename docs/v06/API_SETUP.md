# 서구온 v0.6 · 재난안전 API 9종과 키 통합 설정

## 현재 상태

공식 서비스별 요청·출력 명세를 대조하여 9종 어댑터를 작성했습니다. 실제 사용자 키로 9종 수신을 완료하지 않았습니다. 한파쉼터에 대한 제한된 1회 연결 시도는 제작환경의 네트워크 문제로 실패했으며, 키 유효성·허용 IP가 맞는지는 판정하지 않았습니다. Vercel에는 값을 직접 저장하지 않았습니다.

## 1. 변수 하나로 9개 서비스키 등록

`tools/safety-key-import.html`을 본인 컴퓨터에서 엽니다. 플랫폼에서 복사한 서비스 주소와 키를 포함한 발급 내역을 붙여넣고 ‘발급 내역에서 찾기’를 누릅니다. 9개를 확인한 다음 ‘JSON 만들고 복사’를 누릅니다. 클립보드 접근이 막혔다면 ‘복사할 값 화면에 보기’ 후 Ctrl+C로 복사합니다.

Vercel → seogu-on → Settings → Environment Variables에서 아래 **변수 하나**를 만듭니다.

```text
SAFETYDATA_KEYS_JSON
```

Value에는 도우미가 만든 JSON 전체를 넣습니다. Production에 적용하고, 제공되는 경우 Sensitive를 켜서 저장 후 재배포합니다. 도우미에는 실제 키가 없고 네트워크 요청·서버 전송·localStorage 저장을 하지 않습니다. 키를 정리하는 탭의 메모리와 복사한 클립보드에 값이 남을 수 있으므로 사용 후 지우고 닫으세요. 키가 입력된 화면을 공유하지 마세요.

통합 JSON의 구조는 `{"DSSP-IF-10804":"본인의 해당 키", "DSSP-IF-10942":"본인의 해당 키"}`입니다. 예시 설명 문장이 아니라 실제 키를 도우미로 정리해서 넣어야 합니다. 개별 환경변수가 이미 존재하면 아래 표의 개별 값이 통합 JSON보다 우선합니다.

## 3. 허용 IP와 실제 인증

사용자가 발급내역에서 확인한 ‘유저아이피’가 Vercel에서 실제 호출하는 서버의 출발 IP와 같은지는 아직 확인되지 않았습니다. 공식 응답 코드 32는 등록되지 않은 IP를 뜻합니다. 이 오류가 나오면 제공기관에서 허용되는 서버 IP 등록 방법과 Vercel의 출발 IP 조건을 확인해야 합니다. 코드에서 IP를 위조하거나 공개 우회 프록시로 해결하지 않습니다.

30/31/33은 키 등록·유효기간·존재를 확인하고, 22는 호출 한도를 확인합니다. 단순 HTTP200도 정상 데이터 수신을 보장하지 않으므로 응답 안의 오류코드를 검사합니다. 내부 URL·키·원본 오류문에 든 비밀값은 화면으로 복사하지 않습니다.

## 4. 100회/일 한도 보호와 수집 완전성

사용자의 클릭으로만 시작하며 페이지당 500행, 한 차례에 최대 4페이지까지 요청한 뒤 수집 중이면 ‘계속 수집’으로 이어갑니다. 마지막 정상 자료는 전체 페이지의 일관성 검사가 끝나기 전까지 교체하지 않습니다. 부분수집은 검수 대기이며 전체 현황으로 표시하지 않습니다.

AWS·병상·도로는 15분, 나머지는 1시간 서버 인스턴스 캐시를 사용합니다. 인증·한도 오류 후 짧은 재시도 대기와 이전 정상 자료의 시각 표시도 적용합니다. **서버리스 인스턴스 간 공유되는 영구 캐시나 계정 전체의 정확한 일일 한도 차감기는 아닙니다.** 여러 사용자가 자주 조회하면 공유 캐시·별도 수집 작업이 필요합니다.

한파·무더위만 문서화된 bbox로 줄여 요청합니다. 다른 서비스는 존재를 확인하지 못한 ‘서구 필터’를 임의로 만들지 않았으므로 전국 원본 페이지를 읽은 뒤 서구 경계로 검사하는 경우가 있습니다. 첫 4페이지에 서구 자료가 없다고 전체 서구 시설이 없다는 뜻은 아닙니다.

## 5. 좌표가 없는 AWS·병상·위험지구

이 서비스들은 공식 출력항목에서 좌표를 확인하지 못했습니다. 지점의 이름을 추측해 배치하지 않습니다. `SAFETYDATA_LOCATION_INDEX_JSON`에 **원자료 고유번호와 정확히 대응하며 검수한 위치**를 넣는 별도 구조를 준비했습니다.

대조표 키는 `sd-aws`, `sd-beds`, `sd-risk`이며 내부에 실제 관측소·의료기관·지구 식별번호를 넣습니다. 항목에는 `name`, `longitude`, `latitude`, `sourceName`, `sourceDate`, `verified: true`가 필요합니다. 검수되지 않은 위치는 `verified: false`로 남기며 지도에 쓰지 않습니다. 원자료 기준일을 모르면 임의로 오늘 날짜를 넣지 마세요.

AWS는 이 검수 관측소가 없으면 전국 시계열을 무작정 조회하지 않습니다. 패널에서 해당 관측소 코드를 선택/입력한 뒤 요청합니다. 병상정보의 응급실 등 숫자는 원자료 항목명을 유지하며, 실제 수용 가능 여부를 보장하지 않습니다. 당직의사명·직통연락처·작성자 등 불필요한 개인 속성은 전달하지 않습니다.

## 6. 침수흔적과 도로정보

침수흔적도 GEOM의 실제 응답이 WKT·투영좌표 등으로 오면 현 상태에서 임의 좌표계로 변환하지 않고 보류합니다. WGS84 GeoJSON으로 검증한 도형만 지도에 넣습니다. 원자료 포맷을 확인한 뒤 해당 변환기를 추가해야 합니다.

도로위험 원자료에 발행시각이 없다면 수집시각을 대신 ‘예보 발표시각’으로 표시하지 않습니다. 점 위치를 임의 도로선형으로 이어 붙이지 않습니다. 민방위 대피소를 모든 재난에 적합한 대피소로 분류하지 않습니다.

## 7. 기존 키는 보존

브이월드, 기상청, 에어코리아, ITS 등의 기존 변수는 그대로 유지합니다. 새 AWS 서비스키는 기존 `KMA_SERVICE_KEY`와 별개이며, 새로운 재난안전 키를 `SAFEMAP_SERVICE_KEY` 같은 다른 기관 변수에 넣어서는 안 됩니다. API 발급 주체와 서비스마다 키가 다릅니다.

사용자에게서 받은 키를 GitHub·ZIP·HTML·로그에 넣지 않았습니다. 채팅에 게시된 키는 운영 전에 필요에 따라 순차 재발급하고 같은 통합 변수 값을 갱신하는 방법을 권합니다.
