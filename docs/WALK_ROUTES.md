# 생활도보길: 방문·점검을 위한 보행 경로 비교

문서 확인일: 2026-10-27. 공개 시설자료와 TMAP 보행자 경로를 연결해, 담당자가 시설 방문이나 현장점검을 준비할 때 **어느 시설을 어떤 순서로 거치고 얼마나 더 걷는지** 비교한다.

‘안심시설 경유’는 공개된 경찰시설 등을 거치는 경로라는 뜻이다. 범죄위험을 평가하거나 검증된 여성안전 경로를 인증하는 서비스가 아니다. 그늘막·쉼터 경유도 경로 전체의 그늘, 체감온도 저감, 현재 개방을 검증하지 않는다.

## 사용 순서

1. **생활도보길** 메뉴에서 **그늘·쉼터경유 / 안심시설경유 / 돌봄방문 / 현장점검** 중 목적을 선택한다.
2. 현재 지역의 수록 시설 목록에서 출발·도착을 고르거나 **지도에서 선택**한다. 처음에는 **예시 출발·도착 선택**으로 실제 수록 시설 두 곳을 불러올 수 있다.
3. 필요하면 계단 제외 옵션을 선택한다. 이 옵션은 계단을 피하는 탐색조건이며, 휠체어·유모차 이용에 필요한 경사·턱·도로폭·승강기 가동을 검증하지 않는다.
4. 현장점검은 **방문할 점검지**를 최대 3곳 직접 선택하고 위·아래 버튼으로 방문 순서를 정한다. 같은 건물의 회의실을 여러 방문지로 넣지 않도록 위치와 주소를 함께 확인한다.
5. **도보경로 비교**를 누르면 TMAP을 호출한다. 결과에서 **바로 가는 경로**와 각 경유안의 거리·예상 보행시간·추가 거리·추가 시간을 비교한다.
6. **지도 보기**로 선택한 경로를 확인하고, 출발·도착과 경유 시설의 실제 출입구·개방 여부를 대조한다. 예상 보행시간에는 시설 체류·상담·점검·대기 시간이 포함되지 않는다.

목록을 고르거나 지도에서 위치를 선택하는 것과 실제 경로 수신은 구분한다. API 실패 시 직선 또는 모의 선을 실제 보행경로로 표시하지 않는다. 시설 미연결, 인증 실패, 호출한도, 경로 미수신을 시설 부재나 도보 연결 불가로 단정하지 않는다.

## TMAP 연결

서버 환경변수 **`TMAP_API_KEY`**에 승인된 TMAP 앱키를 저장한다. **`TMAP_APP_KEY`**는 호환 별칭이며 두 값이 있으면 기본 변수 `TMAP_API_KEY`를 우선 사용한다. 키를 브라우저 공개 변수, 소스, 문서, 지도 URL 또는 로그에 넣지 않는다. 키 설정 후 환경변수가 반영되도록 재배포한다. 이 문서는 키 값을 조회하거나 시험하지 않았다.

공식 API는 `POST https://apis.openapi.sk.com/tmap/routes/pedestrian?version=1`이며 `appKey` 헤더를 사용한다. 출발·도착 좌표와 명칭, 좌표계, 탐색옵션을 보낸다. WGS84 경도·위도 순서를 유지한다.

공식 보행자 명세에는 추천(0), 대로 우선 추천(4), 최단(10), 계단을 제외한 최단(30) 옵션이 있다. 이 앱이 사용하는 기본 비교는 최단과 계단 제외 조건이며, ‘최적 그늘’, ‘범죄 회피’, ‘안전 보장’, ‘무장애 인증’ 옵션은 아니다. 공식 `passList`는 입력 순서대로 최대 5곳의 경유 좌표를 지원한다. 앱의 최대 3시설 점검 제한과 순서 선택은 업무 범위를 줄이기 위한 앱 기능이며 TMAP의 전역 최적 방문순서 보장을 뜻하지 않는다.

공식 문서:

- [TMAP 보행자 경로안내 명세](https://tmap-skopenapi.readme.io/reference/보행자-경로안내)
- [TMAP API 공식 안내](https://tmapapi.tmapmobility.com/)
- [SK open API TMAP 상품·앱 관리](https://openapi.sk.com/products/detail?linkMenuSeq=37)
- [TMAP API 이용약관](https://tmapapi.tmapmobility.com/terms.html)

실제 사용권한·요금·호출한도는 해당 앱의 가입 상품과 관리화면에서 확인한다. 무료 호출량을 근거 없이 고정값으로 약속하지 않는다.

### 앱 내부 조회 계약

`GET /api/walk-routes?region=seogu` 또는 `region=suncheon`은 지역별 후보·설정 여부·경유 가능 여부와 자료 경고를 반환한다. 이 호출만으로 TMAP 경로를 요청하지 않는다. 후보의 `routeEligible:false`는 위치 참고용이며 경유 선택을 허용하지 않는다.

`POST /api/walk-routes`에는 `regionId`, `mode`(`shade|safety|care|inspection`), `start:[경도,위도]`, `end:[경도,위도]`, `avoidStairs`, 필요 시 `viaIds`를 보낸다. 결과는 조회시각, 유효시각, 직접경로와 수신에 성공한 경유안, 거리(m), 예상시간(초), 지도 선과 경유시설 출처를 포함한다. 점검모드는 지정한 최대 3곳을 지정 순서대로 잇는다. 다른 모드의 후보는 최대 두 개의 단일 경유안으로 직접경로와 비교한다.

경로의 앱 유효기간은 30분이며 도로 통행상태를 실시간 감시한다는 뜻은 아니다. 요청 지점 간 직선거리 및 수신 경로가 각각 10km를 넘으면 허용하지 않는다. 요청당 TMAP 호출은 최대 3회다. `TMAP_DAILY_LIMIT`의 기본값은 하루 300회 호출시도, `0`은 비활성화다. IP당 분당 3회 요청 제한과 일일 카운트는 서버 인스턴스 안의 최선형 제한이므로 Vercel 전체의 확정 과금상한으로 광고하지 않는다. 제공기관 상품의 한도 설정도 함께 확인한다. 일부 경유안이 실패하면 정상 수신한 경로와 경고를 반환하고, 모두 실패하면 오류를 반환한다.

현재 경로 결과의 영구 저장·다운로드는 제공하지 않는다. 점검메모를 화면에서 비교할 수 있는 것과 공식 출장명령·안전확인·현장점검 이력 저장은 별개의 업무다.

## 실무 효용을 높이는 우선 개선

1. **하루 점검 업무를 산출물로 끝낸다.** 최대 3시설 방문목록, 선택 순서, 구간별 보행시간, 별도 체류시간, 확인할 사항을 한 표로 정리하면 전화·메모·지도 사이의 왕복을 줄일 수 있다. 체류시간이 비어 있으면 총 출장시간을 자동 확정하지 않는다.
2. **우회의 대가를 먼저 보여준다.** 시설을 하나 더 거칠 때 직접경로 대비 몇 m·몇 분이 늘어나는지 가장 먼저 제시한다. 운영 미확인인 쉼터를 이유 없이 멀리 돌아가게 하지 않도록 선택권을 남긴다.
3. **시설을 보고 바로 확인업무로 이어진다.** 시설유형·출입구 검수상태·공시 기준일·기관 전화·방문약속 여부를 함께 보여준다. 어린이집의 정원 차이를 입소 여석으로, 경찰시설 존재를 안전 점수로 변환하지 않는다.
4. **건물과 방, 참고지점과 실제 입구를 구분한다.** 같은 좌표의 여러 회의실 선택을 안내하고, 건물 중심이 아닌 검수된 보행 출입구를 별도 필드로 사용할 수 있어야 한다. 대표좌표를 입구로 조용히 바꾸지 않는다.
5. **갱신이 업무 판단에 반영되게 한다.** 입구 폐쇄·휴관·그늘막 미가동·비상벨 고장 확인 후 해당 경유안을 재검토하고, 과거 결과에는 당시 출처·조회시각·시설 상태를 남긴다. 관측 시각이 지난 운영정보를 현재 확인값으로 유지하지 않는다.

공통 입력은 `facilityId`, 원자료 식별자, 보행 출입구 경도·위도, 출입조건, 운영요일·시간/휴관, 현장 확인시각, 상태 유효시각, 공개 가능한 근거다. 관찰자 개인 이름이나 시설 이용자 개인정보를 공개 지도에 넣을 필요는 없다. 확인된 출입구는 원문 대표좌표와 별도 보관한다.

## 추가 API·자료의 우선순위

| 우선 | 추가 자료 | 이유와 현재 한계 |
|---|---|---|
| 1 | TMAP 보행자 경로 사용권한과 서버 키 | 실제 보행 선·거리·예상시간을 받는 데 필요하다. 현재 자료와 연결할 때 가장 직접적인 추가 API다. |
| 1 | 위 10곳의 입구·개방·임시폐쇄·방문조건 | 경유지의 실제 이용 가능성을 높이는 데 API 수 증가보다 중요하다. 지자체 시설관리자료·현장 확인으로 확보한다. |
| 2 | 비상벨 최신 점검일·작동/연계 상태·공개 접근 가능 위치 | 2023년 공개목록만으로 실외 접근성과 현행 작동을 판단할 수 없다. 관리부서의 공개 가능한 점검자료가 필요하다. |
| 2 | 그늘막 가동·보수·계절 운영과 쉼터 개방시간 | 설치 좌표를 이용 가능한 휴식지점으로 연결하는 근거다. 현행성·유효기간을 표시한다. |
| 3 | 보도 폭·턱·경사·횡단·승강기 가동·공사 통제 | 유모차·휠체어 경로 품질을 다루려면 필요하다. 계단 제외 한 옵션으로 대체할 수 없다. |
| 3 | 검증된 건물 높이·수목 수관·보행구간별 시각별 일사/그늘 | 향후 ‘그늘이 많은 경로’ 비교를 하려면 필요하다. 그늘막 대표점 개수만으로 전 구간 그늘 비율을 계산하지 않는다. |

주소 검색 편의를 위해 지오코딩이나 POI API를 추가할 수 있지만 반환 좌표는 입구 검수의 대체물이 아니다. 기상청 등 기존 연결은 환경정보 보조에 재사용할 수 있으며, 기온만으로 개인별 보행 안전을 판정하지 않는다. 이 단계에서는 TMAP 외에 새 키를 여러 개 요구하기보다 실제 시설 5~10곳의 검증된 방문 사례를 완성한다.
