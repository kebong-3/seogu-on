**공공데이터를 지도에서 살펴보고, 대안을 비교하고, 검토보고서로 남깁니다.**

## 1. 어떤 문제를 해결하나요?

지역 현황을 검토할 때는 여러 누리집에서 공개자료를 찾고, 주소를 지도와 대조하고, 검토메모와 보고서를 다시 작성해야 합니다. 서구온은 이 작업을 하나의 흐름으로 연결하는 **공개자료 기반 행정 검토용 프로토타입**입니다.

- **주민**은 동네의 공원·도서관·돌봄·복지·생활안전 관련 정보를 지도에서 찾아봅니다.
- **공무원**은 시설 분포, 추가·이전·중단에 따른 변화, 사업 후보지의 주변 여건을 비교하고 현장점검을 준비합니다.
- **AI**는 자연어 질문을 자료 조회·계산 조건으로 연결하거나, 조회 도구가 계산한 근거와 후속 확인사항을 설명합니다. 거리와 비교 수치는 공간 계산 도구가 산출합니다.

현실의 공간자료와 담당자의 확인기록을 바탕으로 변경안을 비교하고, 조건이나 확인기록을 바꾸면 다시 계산하는 업무 단위 디지털트윈입니다. 자료의 출처·기준일·미확인 사항을 결과와 함께 확인하도록 구성했습니다.

## 2. 주요 기능

| 기능 | 할 수 있는 일 | 확인하거나 저장하는 결과 |
|---|---|---|
| **생활시설 지도** | 지역·동·시설 종류·명칭·주소로 학교, 공원, 도서관, 돌봄·복지시설 등을 찾습니다. | 위치, 시설정보, 출처와 기준일 |
| **지도에게 묻기** | “풍암동 공원 위치 알려줘”처럼 질문하고 관련 자료와 계산 근거를 확인합니다. | 지도 결과, 근거, 담당자 확인사항, 검토메모 |
| **시설 배치 대안 비교** | 시설을 추가·이전·제외하거나 기존 시설이 중단되는 조건에서 전후 차이를 계산합니다. | 지정 거리조건에 따른 변화, 검토서·CSV |
| **사업 후보지 비교** | 두 위치 주변의 학교·생활시설·수록 기록을 같은 반경으로 비교합니다. | 동일 조건의 후보지 비교자료 |
| **계절 대응·현장점검** | 폭염·한파 대응안을 비교하고 결빙 관리지점, 침수 이력, 통학환경을 점검할 자료를 준비합니다. | 검토대상, 담당부서·기한·현장 기록, HTML 보고서·인쇄/PDF |
| **공공공간 운영 검토** | 확인한 개방요일·시간과 추가 운영비 가정을 바꾸어 운영 대안을 비교합니다. | 조건 충족 공간 수, 미확인 수, 비용 가정, 비교기록 |
| **계절별 생활도보길** | 외부 보행경로와 확보한 건물자료를 이용해 후보 경로의 거리·시간·그늘·일조 부족 등을 살펴봅니다. | 실제 조회 후보의 비교와 자료 미확인 범위 |
| **검토노트·보고서** | 질문·근거·담당자 확인사항을 저장하고 업무 메모를 이어서 작성합니다. | TXT 메모, HTML 보고서, 노트 JSON 백업 |
| **다른 지역 적용** | 서구와 순천의 지역 설정·경계·수록 자료를 바꾸어 지원 업무를 실행합니다. | 지역별 조회·비교 결과와 자료 수록 범위 |

서구와 순천은 수록 자료와 지원 업무가 다릅니다. 지도·AI·보행경로 등 외부 서비스는 연결 설정과 실제 응답 여부에 따라 작동합니다. 그늘·거리 모형은 현재 안전도나 최적 경로를 보장하는 결과가 아닙니다.

## 3. 실제 사용 순서

### 3-1. 주민 문의: 동네 공원을 찾고 메모 남기기

1. [체험 주소](https://seogu-on.vercel.app/)에 접속해 **서구 → 풍암동**을 선택합니다.
2. 상단 **지도에게 묻기**에 **“풍암동 공원 위치 알려줘”**를 입력합니다. 생활시설 메뉴에서 공원을 선택해 찾아볼 수도 있습니다.
3. 결과 목록과 지도 위치를 확인하고 **출처·기준일·수록 범위**를 살펴봅니다.
4. **검토메모 복사** 또는 **검토메모 저장**을 눌러 질문, 근거, 확인사항을 보관합니다.

**확인할 결과:** 선택한 동의 수록 공원과 그 근거가 표시되는지 확인합니다. 결과가 없으면 자료 미수록·조회 실패 등 표시된 원인을 확인합니다.

### 3-2. 행정 검토: 폭염 대응 대안을 비교하고 보고서 저장하기

1. 홈에서 **폭염 대응계획**을 열고 검토 구역, 그늘막·쉼터 거리조건, 신규 후보 상한을 정합니다.
2. **두 안 비교하기**를 눌러 기존 쉼터 활용안과 추가 설치 후보를 더한 검토안을 비교합니다.
3. 필요한 경우 운영비·설치비·유지비와 검토기간을 입력합니다. 입력하지 않은 비용은 **미산정**으로 남습니다.
4. 후보의 위치와 근거를 확인하고 현장 확인내용, 보류 사유, 선호안과 선정 근거를 기록합니다.
5. 보고서를 미리 본 뒤 **HTML 내려받기** 또는 **인쇄 → PDF로 저장**을 실행합니다.

**확인할 결과:** 선택 구역·거리조건·비용 가정·담당자 기록이 보고서에도 동일하게 담기는지 확인합니다. 거리조건은 사용자의 검토 가정이며 법정 설치기준이나 실제 위험 감소 효과를 뜻하지 않습니다.

### 3-3. 현장점검: 과거 침수 이력으로 확인목록 만들기

1. **침수 이력 현장점검**을 열어 검토 구역을 고릅니다.
2. **검토대상 불러오기**를 누르고 과거 기록의 발생연도·대표위치·출처를 확인합니다.
3. 담당부서, 확인기한, 현장 확인내용과 검토의견을 기록합니다.
4. 검토보고서를 미리 보고 HTML 또는 인쇄/PDF로 저장합니다.

**확인할 결과:** 과거 이력과 담당자가 입력한 확인기록이 구분되어 있는지 확인합니다. 과거 침수 기록을 현재 위험도나 미래 침수 예측으로 해석하지 않습니다.

자세한 사용법: [AI 질의·검토노트](docs/AI_PANEL.md) · [폭염 대응계획](docs/HEAT_REVIEW.md) · [계절 대응·현장점검](docs/ADMIN_WORKFLOWS.md) · [시설·후보지 비교](docs/DECISION_TWIN.md)

## 4. 내 컴퓨터에서 실행하기

### 4-1. 준비물

| 항목 | 필요한 내용 |
|---|---|
| 실행환경 | **Node.js 22.9 이상인 22.x 버전** · 최신 22.x 권장 · [Node.js 공식 다운로드](https://nodejs.org/en/download) |
| 브라우저 | 최신 Chrome 또는 Edge 등 · 3D 지도는 WebGL을 사용할 수 있는 환경 필요 |
| 프로젝트 파일 | **저장소 전체**를 폴더 구조 그대로 준비합니다. `vendor/cesium-1.121.0.tar.gz`와 `vendor/cesium-manifest.json`을 포함합니다. |
| 추가 패키지 설치 | 일반 실행에 **`npm install`은 필요하지 않습니다.** 지도 엔진 압축은 Node.js가 직접 처리합니다. |
| 외부 연결 | 실제 AI 답변·브이월드 지도·기상·TMAP 등은 해당 서비스 키와 접근 가능한 네트워크 필요 |

Node.js 런타임은 프로젝트에 포함하지 않습니다. `.cmd`와 `.sh`는 설치된 Node.js로 서버를 시작하는 **실행 도우미**입니다. 일반 실행에는 Git과 Python이 필요하지 않으며, 전체 자동검증에는 Python 3도 사용합니다.

### 4-2. Windows에서 실행하기

1. 프로젝트 전체 ZIP을 내려받아 **압축을 모두 해제**합니다. ZIP 안에서 실행하지 않습니다.
2. `README.md`, `package.json`, `start-seoguon.cmd`가 함께 보이는 폴더를 엽니다.
3. Node.js 22.x를 설치한 뒤 **`start-seoguon.cmd`를 더블클릭**합니다.
4. 실행 창에 `SEO:ON running: http://127.0.0.1:4173`가 나오면 브라우저에서 해당 주소를 엽니다. 다른 포트를 설정했다면 실행 창에 표시된 주소를 사용합니다.
5. 사용하는 동안 실행 창을 열어 두고, 종료할 때는 그 창에서 **Ctrl+C**를 누릅니다.

Windows에서 실행 도우미 대신 명령으로 실행하려면 프로젝트 폴더의 파일 탐색기 주소창에 `cmd`를 입력해 명령 프롬프트를 연 뒤 다음을 입력합니다.

```bat
node --version
npm run dev
```

### 4-3. macOS·Linux 또는 터미널에서 실행하기

`package.json`이 있는 프로젝트 폴더에서 다음을 실행합니다.

```sh
sh start-seoguon.sh
```

공통 실행 명령은 `npm run dev`입니다. 서버가 준비되면 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)에 접속하고, 종료할 때는 **Ctrl+C**를 누릅니다. 로컬 서버는 실행한 컴퓨터의 `127.0.0.1`에서만 접속할 수 있습니다.

### 4-4. API 키 없이 먼저 확인하기

`.env.local`을 만들지 않아도 서버를 실행할 수 있습니다. **[경계도 모드로 열기](http://127.0.0.1:4173/?map=boundary)**에서 수록 공개자료 조회, 기본 공간계산, 검토기록과 보고서 흐름을 확인합니다. AI 연결이 없으면 질문 결과에 **규칙 기반**으로 표시합니다.

`index.html`을 더블클릭해 `file://`로 여는 방식은 서버 API를 실행하지 못합니다. 기본 자료 체험과 외부 지도·AI·API의 정상 연결 여부는 따로 확인합니다.

## 5. API·AI 연결 설정

로컬에서 외부 기능까지 사용하려면 최상위의 **[.env.example](.env.example)**을 복사해 **`.env.local`**로 저장하고, 사용할 서비스의 값만 입력합니다. `npm run dev`와 실행 도우미는 이 파일을 자동으로 읽습니다. 설정 변경 후에는 서버를 종료하고 다시 실행합니다.

| 기능 | 주요 환경변수 | 설정 안내 |
|---|---|---|
| 브이월드 3D 지도 | `VWORLD_BROWSER_KEY`, `VWORLD_DOMAIN` | 실제 접속 주소에 대한 제공기관의 도메인 등록 필요 |
| 브이월드 조회·주제도 | `VWORLD_API_KEY` | 서버에서 조회하는 키 |
| Google 계열 AI | `AI_PROVIDER`, `AI_MODEL`, `GEMINI_API_KEY` | [AI 연결 안내](docs/AI_PANEL.md)의 설정에 따라 사용 |
| Upstage Solar | `AI_PROVIDER`, `AI_MODEL`, `UPSTAGE_API_KEY` | [Solar 연결 안내](docs/SOLAR_SETUP.md)에 따라 공급자와 모델을 함께 설정 |
| 기관의 호환 모델 서버 | `AI_PROVIDER`, `AI_MODEL`, `AI_API_BASE`, `AI_API_KEY` | 지원 규격·접근권한을 갖춘 모델 서버 연결 |
| 기상·공공자료 | `DATA_GO_KR_SERVICE_KEY`, `KMA_SERVICE_KEY` 등 | 서비스별 활용신청·인증 조건 확인 |
| 재난안전 자료 | `SAFETYDATA_KEYS_JSON`, 개별 `SAFETYDATA_…_KEY` 등 | 서비스별 승인·허용 IP 등 확인 |
| 생활도보길 | `TMAP_API_KEY` 또는 `TMAP_APP_KEY` | 보행경로·장소·주소 검색 이용권한 확인 |

전체 설정과 오류 코드는 [API 설정 안내](docs/API_SETUP.md)를 확인합니다. 사용할 모델 이름은 제공기관에서 실제 사용 가능한 값으로 설정합니다. 환경변수가 있다는 사실만으로 API 인증이나 모델 호출의 성공이 확인되는 것은 아닙니다.

- 실제 키가 들어 있는 **`.env.local`을 GitHub·공공 GitLab·제출 ZIP에 넣지 않습니다.** 공개하는 설정 파일은 실제 키가 비어 있는 `.env.example`입니다.
- 배포 서버에서는 서버의 환경변수 기능을 사용합니다. 기존 Vercel 연동 배포의 설정은 [배포 안내](docs/DEPLOY_VERCEL.md)를 참고합니다.
- AI 질문·검토내용은 연결한 모델 제공기관으로 전송될 수 있습니다. 공개자료를 이용하고 개인정보·비공개 업무정보를 입력하지 않습니다.

## 6. 프로젝트에 함께 등록하는 실행자료

### 제공 형태와 포함 파일

**실행자료는 웹 애플리케이션 전체 소스와 데이터, 지도 엔진 자료, 실행 도우미를 함께 담은 프로젝트입니다.** 전체 소스 ZIP을 풀어 위 로컬 실행 절차로 구동합니다. 단일 Windows `.exe`나 Node.js 설치 프로그램을 포함하는 형식은 아닙니다.

| 파일·폴더 | 역할 |
|---|---|
| `README.md`, `START_HERE.md` | 접속 주소, 주요 기능, 실행·사용 방법 |
| `start-seoguon.cmd` | Windows 실행 도우미 |
| `start-seoguon.sh` | macOS·Linux 실행 도우미 |
| `package.json`, `scripts/` | 실행·빌드·검증 명령과 스크립트 |
| `index.html`, `classic.html`, `src/`, `shared/` | 화면·공통 계산 코드 |
| `api/`, `server/`, `vercel.json` | 서버 API·AI 연결·배포 경로 설정 |
| `public/` | 지역 경계·공개자료·화면 자원 |
| `vendor/` | 고정 버전 지도 엔진 압축본과 무결성 정보 |
| `.env.example` | 실제 키를 제외한 연결 설정 예시 |
| `docs/`, `tests/`, `LICENSE`, `THIRD_PARTY_NOTICES.md` | 사용·운영·검증 문서, 자동시험, 이용조건 |

제출할 때는 **README가 프로젝트 최상위에서 바로 보이도록** 전체 폴더 구조를 유지합니다. `dist/`는 정적 화면 빌드 결과이므로, 이것만 등록하면 서버 API와 전체 실행 구성이 빠집니다. 별도 실행 형식이나 첨부 방식이 지정된 경우에는 행사 안내서의 해당 조건을 적용합니다.

### 검증한 소스 ZIP과 기록 내려받기

GitHub 저장소의 **Actions → Challenge reproducible evidence**에서 제출할 커밋과 일치하는 **성공한 실행**을 선택합니다. 하단 아티팩트 `seoguon-verified-source-커밋번호`를 내려받아 열면 다음이 들어 있습니다.

| 파일 | 내용 |
|---|---|
| `seogu-on-source.zip` | 해당 커밋의 전체 추적 소스·데이터·실행 도우미 |
| `source-manifest.json` | 커밋, 버전, 실행환경, 파일별 SHA-256 |
| `SHA256SUMS.txt` | 소스 ZIP의 SHA-256 |
| `verify.log` | 문법·단위시험·빌드·배포 묶음 검사 기록 |
| `region-replay.json` | 실제 순천 공개자료를 이용한 지역 재현 기록 |

아티팩트 ZIP 안의 `seogu-on-source.zip`까지 풀어야 실행 폴더가 나옵니다. Actions 아티팩트의 보관기간은 현재 워크플로 기준 30일이므로, **제출할 소스와 필요한 기록은 공공 GitLab 프로젝트에도 함께 등록**합니다. 단순히 Actions 링크만 남기지 않습니다.

개발자가 Git 체크아웃에서 같은 소스 묶음을 만들 때는 검증 후 `node scripts/package-challenge.mjs`를 실행합니다. 이 명령은 Git과 커밋 이력이 필요합니다. 일반 다운로드 ZIP에는 `.git`이 없으므로 **앱 실행은 가능하지만 해당 Git 패키징 명령은 실행할 수 없습니다.**

## 7. 검증과 배포용 빌드

Node.js 22.x와 Python 3가 있는 환경에서 다음을 실행합니다. 일부 자동시험이 `python3` 명령을 사용하므로 Windows에서는 WSL 또는 저장소의 GitHub Actions 검증 환경을 활용할 수 있습니다.

```sh
npm run verify
node scripts/validate-region-replay.mjs --out outputs/region-replay.json
```

`verify`는 **문법 검사 → 단위시험 → 빌드 → 배포 묶음 검사**를 순서대로 수행합니다. 외부 모델 키 없이 확인하는 코드·자료 검증과 실제 AI 호출·외부 지도 수신·직원 업무효과 측정은 서로 다른 검증입니다. 실제 모델과 업무효과를 확인하는 방법은 [검증 실행 안내](docs/VALIDATION_RUNBOOK.md)에 정리했습니다.

배포용 정적 화면을 만들고 로컬에서 미리 볼 때는 다음 명령을 사용합니다.

```sh
npm run build
node --env-file-if-exists=.env.local scripts/dev.mjs --dist
```

미리보기에서도 전체 프로젝트의 서버 API를 사용합니다. 기존 `npm run preview`는 `.env.local`을 자동으로 읽지 않으므로, 로컬 연결 설정까지 적용하려면 위 명령을 사용합니다.

제출 버전은 성공한 실행의 `source-manifest.json`에 있는 커밋으로 확인합니다. 배포 버전은 `/data/release.json`의 버전·코드 지문을 빌드 결과와 대조합니다. 루트의 `RELEASE_MANIFEST.json`은 과거 v0.7.0 기록으로 현재 제출본의 증빙이 아닙니다.

## 8. 실행 중 문제가 생기면

| 증상 | 확인할 내용 |
|---|---|
| Node.js를 찾을 수 없음·지원 버전 오류 | Node.js 22.9 이상인 22.x를 설치하고 실행 창을 다시 엽니다. `node --version`으로 확인합니다. |
| `package.json`·`vendor` 파일 없음 | ZIP 전체를 다시 풀고 `package.json`과 실행 도우미가 함께 있는 폴더인지 확인합니다. |
| `EADDRINUSE` 또는 접속 포트 사용 중 | 이미 실행한 서구온 창이 있는지 확인합니다. 기존 서버를 종료한 뒤 다시 실행하거나 기존 창의 접속 주소를 사용합니다. |
| 브이월드 3D 지도가 표시되지 않음 | 경계도로 기본 흐름을 확인하고 지도 키·등록 도메인·네트워크·WebGL 상태를 점검합니다. |
| 답변에 ‘규칙 기반’ 표시 | AI 미설정·호출 실패·한도 초과 여부를 응답 상태에서 확인합니다. 확보한 자료와 계산 결과는 계속 확인할 수 있습니다. |
| 기상·재난 자료가 ‘미수신’ | API 키·활용승인·허용 IP·제공기관 응답을 확인합니다. 미수신은 해당 시설이나 현상이 없다는 뜻이 아닙니다. |
| 다른 PC에서 검토노트가 보이지 않음 | 기록은 사용한 브라우저에 보관됩니다. 검토노트 JSON 백업·가져오기 또는 보고서 내려받기를 사용합니다. |

## 9. 자료와 해석의 범위

- 공개자료마다 **기준일·수록 범위·갱신 주기·좌표 정확도**가 다릅니다. 수록 건수와 전체 시설 수, 미수신과 0건을 구분합니다.
- 시설의 실제 운영·가동 여부와 현장 접근조건은 담당자의 추가 확인이 필요합니다. 과거 침수기록·결빙 관리지점은 현재 위험 판정이나 예측 결과가 아닙니다.
- 3D 그림자·거리·비용은 확보한 자료와 입력 가정에 따른 계산입니다. 주민 수요, 온도 저감, 실제 안전, 최적 입지 또는 사업 효과를 확정하지 않습니다.
- 검토노트와 현장 입력은 **현재 브라우저**에 보관됩니다. 자동 공동편집·기기 간 동기화·공식 업무시스템 연계는 제공하지 않습니다. 메뉴별 내보내기·복원 범위는 사용 안내를 확인합니다.
- 직원 업무시간 절감 등 효과 수치는 실제 측정 후 제시합니다. [업무 비교 기록 도구](public/tools/seoguon-work-study.html)를 내려받아 브라우저에서 열어 기록할 수 있으며, [측정 방법](docs/challenge/measurement-guide.md)을 함께 제공합니다.
