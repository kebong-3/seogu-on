[순천 바로 열기](https://seogu-on.vercel.app/?region=suncheon) · [순천 실제 데이터와 범위](docs/SUNCHEON_DATA.md) · [변경·검증 기록](docs/RELEASE_v0100.md).

## 1. 무엇을 할 수 있나요

첫 화면에서 지역을 고른 뒤 다음 기능을 사용할 수 있습니다. 상단 날씨 옆 질문칸은 어느 메뉴에서든 바로 입력할 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| **공공공간 활용** | 지도·목록에서 실제 공간을 고르고 현장 확인을 기록한 뒤, 요일·개방시간·추가 운영비 가정의 변경안을 비교합니다. 확인기록을 갱신하면 재계산하며 이전 결과와 차이를 보존합니다. |
| **마을·공간 검토** | 마을의제·공간 비교·기존 공간 활용·사업 연계를 선택하고 제안과 대안을 입력하면, 공개 공간자료와 함께 비교기준·담당자 확인사항을 정리합니다. |
| **지도에게 묻기** | 선택 지역의 수록 자료에 문장으로 질문하고 결과를 지도에서 봅니다. 목적·요일·시간은 확인용 초안으로 공공공간 비교에 넘깁니다. |
| **다른 지역도 적용해보기** | 서구와 순천을 전환합니다. 경계·공간자료·질문·확인기록·운영 비교·보고서가 선택 지역을 기준으로 작동합니다. |
| **생활시설** | 학교·공원·도서관·복지시설 등을 종류별로 골라 봅니다. |

그 아래에는 폭염·한파·결빙·침수 이력·통학환경의 검토 도구가 있습니다. **기타 자료·도구**를 열면 자료 목록과 추가 기능이 나옵니다.

- **5분 그림자**: 날짜·시간을 바꿔 3D 건물 그림자를 봅니다.
- **재난안전 API**: 재난안전데이터공유플랫폼 10종(한파·무더위쉼터, 침수흔적, 민방위 대피소, 상습결빙구간 등)의 조회 메뉴입니다. 목록 등록·키 설정·자료 수신 상태를 각각 확인합니다.
- **상습결빙구간**: 광주 서구를 우선 대상으로 조회하고, 받은 원자료에서 서구에 해당하는 위치를 검수해 표시합니다. 미수신과 정상 응답 후 해당 자료가 없는 경우를 구분합니다.
- **재난 상황판**: 호우·급경사·폭염·한파·화재·어린이 보행 6개 묶음의 자료 수신 상태를 봅니다.
- **공식 주제도**: 브이월드 공식 주제도 66종 목록에서 골라 서구 범위로 조회합니다.
- **생활·정책 검토**: "폭염에 대비할 시설은 어디에 있나요?" 같은 질문 6개로 관련 자료 조합을 봅니다.
- **자료 목록**(CSV 내려받기), **분석 도구**(필지 조회, 지형 단면·경사, 가상 건물 배치, 침수지도 원자료), **저장한 검토노트**, **지도 검토기록**(JSON·HTML 내보내기), **연결 설정**.

### 공공공간 활용: 현황과 대안을 연결하는 디지털트윈

1. 선택한 동의 실제 공공공간을 지도 또는 목록에서 최대 10개 선택합니다. 같은 건물의 회의실·강당이 별개 공간일 수 있습니다.
2. 담당자가 확인한 운영 상태·요일·시간과 확인일·근거를 기록합니다. 원자료 운영시간을 자동으로 현재 운영 사실로 확정하지 않습니다. 기록은 90일 또는 입력한 재확인 기한이 지나면 미확인으로 바뀝니다.
3. 현재 확인기록과 최대 3개의 변경안을 같은 요일·시간으로 계산합니다. 지표는 개방 조건 충족 공간 수, 미확인 수, 공간별 겹치는 개방시간 합계, 입력한 추가 연간 운영비(만원)입니다.
4. AI가 서버에서 재계산한 결과를 해석하고 담당 부서의 후속 확인사항을 제안합니다. AI 실패 시 계산 근거 요약으로 표시하며 숫자 비교는 계속 사용할 수 있습니다.
5. 확인기록을 바꾸면 결과가 달라지고 이력이 남습니다. 검토 결과를 스냅샷으로 보관하고 과거와의 차이를 확인하거나 HTML 보고서·JSON 백업으로 가져갑니다.

이 흐름은 **현실 공간 ↔ 확인 시점이 있는 상태 ↔ 변경안 계산 ↔ 현장 확인 후 재계산**을 구현한 업무 단위 디지털트윈 시제품입니다. 사용자 확인은 기관의 공식 검증이나 승인과 다릅니다. 수요·주민 편익·정밀 보행권·최적 입지·재난 피해를 예측하지 않습니다. 확인기록은 해당 브라우저에 보관되며 조직 간 공동편집·권한관리·공식 업무시스템 연계는 별도 구축이 필요합니다.

### 마을·공간 검토와 후속 기록

검토내용은 최대 1,200자, 비교할 대안은 최대 3개(각 140자)로 입력합니다. AI 연결 성공 시 실제 수록자료와 입력 내용을 연결한 설명을 제공합니다. 공통 비교기준·부서 협의 질문은 업무별 기본 검토 틀이며, 주민 수요·후보지 여건·사업 일정 중복·최적안을 확인한 결과로 표시하지 않습니다. AI 연결에 실패해도 확보한 근거와 입력 대안을 규칙 기반 결과로 보존합니다.

결과의 **검토노트에 저장**을 누르면 담당·협의 부서, 진행상태, 확인기한, 현장확인 메모를 이어서 작성할 수 있습니다. 최대 30개의 노트가 현재 브라우저에 저장됩니다. **검토보고서 HTML**은 인쇄용 파일, **JSON 백업**과 **백업 가져오기**는 노트 보관·이전 기능입니다. 자동 공동편집이나 기기 간 동기화는 제공하지 않습니다. [AI·검토노트 사용 안내](docs/AI_PANEL.md)를 참고하세요.

2026-10-21 개편에서는 안전·복지·교통 도구 버튼과 설명문에 테마별 글자 대비를 일관되게 적용했습니다. 마을·공간 검토는 기존 지도·질문 패널 안에서 이어지며 계절 대응 도구도 계속 사용할 수 있습니다.

그 밖에:

- **18개 동**: 동 카드를 누르면 그 동으로 이동합니다. 공식 마을 BI를 함께 보여 줍니다. "18개 동 자동 둘러보기"도 있습니다.
- **상단 관측정보와 상시 질문창**: 기온·1시간 강수(기상청), 재난 관련 자료 수신 종류 수 옆에서 언제든 지도에 질문할 수 있습니다. 좁은 화면에서는 날씨 아래에 질문창이 표시됩니다.
- **지도 4종**: 브이월드 3D(기본), 밝은 도시모형, OSM 경량 입체지도, 경계도(3D 아님). 브이월드 키가 없거나 연결이 안 될 때는 경계도로 자료를 볼 수 있습니다.
- **동 이름표**: 동 이름을 그대로 표시하며 선택한 동의 이름을 먼저 배치합니다. 이름이 겹치는 축척에서는 일부를 숨기고 확대·이동할 때 다시 표시합니다. 동 카드에는 공식 마을 BI와 이름이 남고 숫자 배지와 지도 번호표는 없습니다.
- **화면 설정**: 테마(시그니처 블루 / 스카이 블루 / 야간 네이비)와 지도 밝기.
- 예전 자료 검수 화면은 `/classic.html`에 남아 있습니다.

### 함께 추가되는 기능

- **지도에게 묻기(AI 질의 패널)**: 서구 공개 공간자료를 조회·계산하고 계절 대응 질문에서는 기상청 대표위치 관측도 함께 확인합니다. 폭염·한파·결빙·침수·통학환경·생활시설의 근거와 담당자 확인사항, 결과 위치를 검토메모로 복사·저장합니다. 명확한 질문은 준비한 근거를 AI가 1회 요약하고, 그 밖에는 AI가 조회 도구를 선택합니다. AI 성공과 규칙 기반 대체 결과를 구분합니다. 설명은 `docs/AI_PANEL.md`.

## 2. 환경변수 (API 키)

키는 **Vercel → 프로젝트 → Settings → Environment Variables**에 넣습니다. 저장한 뒤 **Redeploy**를 해야 반영됩니다.
키가 하나도 없어도 사이트는 열립니다. 그때는 경계도와 저장소에 들어 있는 공개자료만 보입니다.

| 변수 | 넣으면 켜지는 것 | 비고 |
|---|---|---|
| `REGION_PROFILE` | 지역 설정 파일 선택(기본 `seogu`) | `public/data/regions/{지역ID}.json`과 경계·공간자료를 먼저 검증합니다. |
| `VWORLD_BROWSER_KEY` | 브이월드 3D 지도(실제 지형·건물) | 브라우저에 보이는 키입니다. 브이월드에서 도메인 제한을 걸어 두세요. |
| `VWORLD_DOMAIN` | 위 키에 등록한 사이트 주소 | `https://seogu-on.vercel.app` |
| `VWORLD_API_KEY` | 주소·필지 조회, 공식 주제도 66종 | 서버 전용 |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 공통 키. 기상·미세먼지·응급의료·사고다발구역의 기본 키로 쓰입니다. | 서버 전용. Encoding·Decoding 어느 쪽이든 됩니다. |
| `KMA_SERVICE_KEY` | 상단 기온·강수, 지점 예보 | 없으면 `DATA_GO_KR_SERVICE_KEY` 사용 |
| `AIRKOREA_SERVICE_KEY` | 수동 대기질 조회·대기 측정소 (상단 표시 없음) | 없으면 `DATA_GO_KR_SERVICE_KEY` 사용. 포털에서 **측정소정보·대기오염정보 두 API**를 활용신청해야 합니다. |
| `AIRKOREA_REGION_QUERY` | 측정소 검색어 | 기본값 `광주`. 보통 건드리지 않습니다. |
| `SAFETYDATA_KEYS_JSON` | 재난안전 API 10종의 서비스별 키 | 서비스 식별자를 키로 둔 JSON. 개별 `SAFETYDATA_…_KEY` 변수도 사용 가능. [설정 안내](docs/API_SETUP.md) |
| `SAFETYDATA_00120_KEY` | 상습결빙구간(`DSSP-IF-00120`) | Vercel 서버의 Secret 환경변수. [공식 데이터 설명·이용조건](https://www.safetydata.go.kr/disaster-data/view?dataSn=111) |
| `SAFETYDATA_LOCATION_INDEX_JSON` | 좌표가 없는 재난안전 자료(AWS·병상·위험지구)의 검수된 위치표 | 선택 |
| `SAFETYDATA_SERVICE_KEY` | 무더위쉼터(기존 연결) | 선택 |
| `EMERGENCY_SERVICE_KEY` | 응급의료기관 기본정보 | 없으면 `DATA_GO_KR_SERVICE_KEY` 사용 |
| `ITS_API_KEY`, `ITS_CCTV_TYPE`, `ITS_FLOW_ENABLED` | 교통 돌발상황·공개 교통 CCTV·소통정보 | 선택 |
| `TAAS_SERVICE_KEY`, `TAAS_YEAR`, `TAAS_SIDO`, `TAAS_GUGUN` | 사고다발구역 | 없으면 `DATA_GO_KR_SERVICE_KEY` 사용 |
| `SAFEMAP_SERVICE_KEY`, `FLOODMAP_SERVICE_KEY` | 생활안전지도·도시침수지도 | 선택 |
| `INFRA_SOURCES_JSON`, `DATA_SOURCES_JSON` | 추가 공개 API 연결 | 선택. 비우면 `[]` |
| `GEMINI_API_KEY`, `AI_API_KEY`, `AI_PROVIDER`, `AI_MODEL`, `AI_API_BASE`, `ASK_DAILY_LIMIT` | 지도에게 묻기의 AI 답변(선택) | 기본 Gemma 4. 서버 전용 연결 설정으로 자체 모델 서버도 사용할 수 있습니다. 하루 AI 호출 한도 기본 300회. `docs/AI_PANEL.md` |

"설정됨"은 변수가 있다는 뜻입니다. 인증 성공이나 자료 수신 성공을 뜻하지 않습니다.

상습결빙구간의 공식 API 주소는 `https://www.safetydata.go.kr/V2/api/DSSP-IF-00120`입니다. 브라우저가 키를 직접 보내지 않고 서버에서 조회합니다. HTTP 상태가 200이어도 응답 본문의 `resultCode`가 오류이면 수신 성공으로 처리하지 않습니다. 0.8.1 점검에서 확인한 등록 IP 오류(`32`)와 후속 상태는 [변경·확인 기록](docs/v081/RELEASE.md)을 참고하세요.

**상단 값이 "미수신"일 때**는 그 값을 눌러 보세요. 원인 코드(`KEY_REJECTED`, `ACCESS_DENIED` 등)와 확인할 일이 나옵니다. 코드별 점검표는 `docs/API_SETUP.md`에 있습니다.

키 값은 저장소·화면 캡처·채팅에 올리지 마세요. 올렸다면 지우는 것으로 끝내지 말고 발급기관에서 재발급하세요.

## 3. GitHub에 올리는 법

파일을 `main`에 올리면 Vercel이 알아서 다시 배포합니다(4번).

**올리면 안 되는 것**: `.env.local`처럼 키가 든 파일, `node_modules`, `dist`, `.vercel` 폴더.
**빼면 안 되는 것**: `vendor/cesium-1.121.0.tar.gz` (없으면 배포가 실패합니다).

### 방법 A. GitHub 웹 화면에서 올리기 (파일 몇 개만 바꿀 때)

1. <https://github.com> 에서 저장소(`seogu-on`)를 엽니다.
2. 바꿀 파일이 있는 폴더로 들어갑니다. 예: `src/city`.
3. 오른쪽 위 **Add file → Upload files**를 누릅니다.
4. 내 컴퓨터의 파일을 화면에 끌어다 놓습니다. 같은 이름의 파일은 새 것으로 바뀝니다.
5. 아래 "Commit changes" 칸에 무엇을 바꿨는지 한 줄 적습니다. 예: `동 이름표 겹침 수정`.
6. **Commit directly to the `main` branch**가 선택된 것을 확인하고 **Commit changes**를 누릅니다.

알아 둘 점:

- 한 번에 100개까지, 파일 하나는 25MB까지 올릴 수 있습니다. 더 많으면 방법 B를 쓰세요.
- 폴더째 끌어다 놓으면 폴더 구조가 유지됩니다. **반드시 같은 위치에서** 끌어다 놓으세요. 저장소 맨 위에서 `src` 폴더를 놓아야 `src/…`로 들어갑니다.
- 웹 화면에서는 파일을 한 번에 여러 개 **지울 수 없습니다.** 파일을 많이 지우는 변경(이번 문서 정리처럼)은 방법 B로 하세요.
- 웹 업로드는 `.gitignore`의 보호를 받지 않습니다. 키가 든 파일을 끌어다 놓지 않도록 주의하세요.

### 방법 B. GitHub Desktop으로 올리기 (파일이 많거나 지울 것이 있을 때)

처음 한 번:

1. <https://desktop.github.com> 에서 GitHub Desktop을 설치하고 GitHub 계정으로 로그인합니다.
2. **File → Clone repository**에서 `seogu-on`을 고르고, 저장할 폴더를 정한 뒤 **Clone**을 누릅니다.

올릴 때마다:

1. GitHub Desktop 위쪽의 **Fetch origin**을 눌러 최신 상태로 맞춥니다.
2. **Repository → Show in Explorer**(맥은 Show in Finder)로 폴더를 엽니다.
3. 새로 받은 파일을 이 폴더에 덮어씁니다.
   전체를 통째로 바꿀 때는, 숨김 폴더 `.git`만 남기고 안의 내용을 지운 다음 새 파일 전체를 복사해 넣습니다. 이렇게 해야 지워진 파일도 함께 반영됩니다.
4. GitHub Desktop으로 돌아오면 왼쪽에 바뀐 파일 목록이 보입니다. 키가 든 파일이나 `node_modules`, `dist`가 목록에 없는지 봅니다.
5. 왼쪽 아래 **Summary** 칸에 한 줄 설명을 적고 **Commit to main**을 누릅니다.
6. 위쪽의 **Push origin**을 누릅니다. 이때 GitHub에 올라갑니다.

### 올린 뒤 자동 검사

저장소의 **Actions** 탭에서 `CI`가 돌아갑니다. "검사 · 시험 · 빌드"에 초록색 체크가 뜨면 통과입니다.
빨간 ✕가 뜨면 눌러서 마지막 붉은 줄을 확인하세요. "오프라인 화면 시험"은 참고용이라 실패해도 배포는 진행됩니다.

## 4. Vercel이 다시 배포하는 방식

- `main`에 새 커밋이 올라가면 Vercel이 **자동으로** 빌드하고 1~2분 뒤 사이트에 반영합니다.
- 진행 상황: Vercel → 프로젝트 → **Deployments**. 맨 위 항목이 `Ready`면 끝난 것입니다.
- **환경변수만 바꿨을 때는 자동으로 반영되지 않습니다.** Deployments → 맨 위 배포의 ⋯ → **Redeploy**를 누르세요.
- 반영 확인: <https://seogu-on.vercel.app/data/release.json> 의 `builtAt`이 방금 시각인지 봅니다.
- 프로젝트 설정(바꾸지 않습니다): Framework `Other` · Build `npm run build` · Output `dist` · Node.js `22.x`.

자세한 내용과 실패했을 때 볼 곳은 `docs/DEPLOY_VERCEL.md`에 있습니다.

## 5. 내 컴퓨터에서 열어 보기 (선택)

[Node.js 22](https://nodejs.org)를 설치한 뒤 저장소 폴더에서:

```bash
npm run dev      # http://127.0.0.1:4173 에서 열림
npm test         # 단위시험
npm run verify   # 문법 검사 + 시험 + 빌드 + 묶음 점검 (올리기 전 권장)
```

설치할 패키지는 없습니다(`npm install` 불필요).
키 없이 화면만 보려면 <http://127.0.0.1:4173/?map=boundary> (경계도) 또는 `?map=clean`(밝은 도시모형)으로 엽니다.
키를 시험하려면 `.env.example`을 `.env.local`로 복사해 값을 넣습니다. `.env.local`은 GitHub에 올리지 않습니다.

## 6. 자료의 한계 (꼭 읽어 주세요)

- 관측값은 외부 API가 **실제로 정상 응답할 때만** 표시합니다. 받지 못하면 "미수신", 응답에 값이 없으면 "미관측"입니다. 없는 수치를 0으로 표시하지 않습니다.
- 서구 전체의 기온·강수는 대표위치의 기상청 5km 격자값입니다. **동 전체의 실측을 뜻하지 않습니다.**
- 갱신에 실패하면 같은 구역의 이전 정상값을 원래 관측시각과 "갱신 실패" 표시와 함께 보여 줍니다. 다른 동의 값을 옮겨 표시하지 않습니다.
- "재난 자료 n종"은 수신된 관련 지도층의 종류 수입니다. **위험도나 실시간 재난경보가 아닙니다.**
- 3D 그림자는 건물 모형의 시각 표현입니다. 나무·그늘막 자체의 그늘, 구름, 법정 일조권을 계산한 것이 아닙니다. 2D 그늘 면은 확보된 일부 건물의 기하학적 근사입니다.
- OSM 도로망은 보행 가능성과 그늘이 검증된 경로가 아닙니다. **폭염 회피 경로를 자동으로 안내하지 않습니다.**
- 공식 주제도 66종, 재난안전 API 10종, 공식 소스 60개는 등록된 **목록의 수**입니다. 실제로 받은 자료의 수가 아닙니다.
- 상습결빙구간은 원자료에 등록된 구간입니다. 현재 도로가 얼었는지, 통행 가능한지, 제설이 완료됐는지를 실시간으로 알려 주는 자료가 아닙니다. 위치가 확인되지 않은 행은 지도에 임의로 표시하지 않습니다.
- 그늘막·쿨링포그는 서구청 공개본(2026-01-06), 침수피해는 과거 기록(2025-11-24)입니다. 현재 운영·가동 여부나 현재 위험등급이 아닙니다.
- 응급의료기관 정보는 기본 등록자료입니다. 실시간 수용 가능 여부가 아니며 긴급상황은 119가 우선입니다.
- 화면과 내보내기의 "시연/미검수" 표시는 사실 검수가 끝나기 전에 지우지 마세요.
- 실제 브이월드 3D 화면의 건물·그림자 표시는 키와 GPU가 있는 실제 브라우저에서 따로 확인해야 합니다. 저장소의 자동 시험은 경계도 화면과 가짜 응답으로만 확인합니다.

더 자세한 내용: `docs/DATA_AND_LIMITS.md`, 보안 관련: `SECURITY.md`, 자료 출처와 이용조건: `THIRD_PARTY_NOTICES.md`.
